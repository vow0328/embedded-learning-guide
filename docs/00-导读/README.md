# 0. 导读

**这一章解决三个问题：这个行业有哪些位置、你该走哪条路、这份教程该怎么用。**

不要跳过这一章。它只有三篇、一两个小时就能读完，但决定了后面 70 多篇的阅读顺序。很多人的学习效率低，不是因为不努力，而是因为一开始就看错了方向、用错了方法。

| 篇目 | 内容 | 读完后你会知道 |
|---|---|---|
| [0.1 嵌入式岗位图谱](01-嵌入式岗位图谱.md) | 12 个岗位的典型画像、技能要求、行业分布；技能→岗位反查表；软硬件边界 | 自己大概想去哪个位置 |
| [0.2 三条路线与技能依赖](02-三条路线与技能依赖.md) | 软件/硬件/全栈三条路线；技能依赖关系图；三条路线的具体阅读顺序；切换路线的时机 | 自己该按什么顺序学、下一步读哪篇 |
| [0.3 怎么用这份教程](03-怎么用这份教程.md) | 项目驱动的使用方法；各章难度与投入；装备采购清单（三档预算）；六个常见学习误区 | 今天该买什么、该做什么 |

## 适合谁

所有人。无论你是零基础学生、转行的程序员，还是想补短板的在职工程师，都建议先花两小时把这三篇读完。

## 建议读法

**按顺序读完三篇**，不要跳。三篇之间是递进关系：先看清地图（0.1），再确定路线（0.2），最后知道怎么动手（0.3）。

读完后做一个动作：**在笔记里写下"三个月内我要做出来的那个东西是什么"**。写不出来，就回到 [0.1](01-嵌入式岗位图谱.md) 重看一遍岗位表，或者直接按 [0.3](03-怎么用这份教程.md) 的采购清单先买一套最小装备。
