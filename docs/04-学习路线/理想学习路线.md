# 4. 仅存于设想中的理想学习路线

以下内容只是作者个人设想中的一条"相对理想"的学习路径，并不适用于所有人。每个人的基础、兴趣、实验室条件、时间分配和目标都不一样，所以这部分更适合当作一个参考框架，而不是必须照搬的标准答案。

## 大一上：打好编程基础，先把方向看清楚

由于东风和科学校区分设，不少实验室位于科学校区，大一阶段往往很难及时获得实验室的硬件支持。再加上很多同学进入大学后才真正开始接触计算机，对嵌入式、电控、算法这些方向几乎没有具体概念，所以这个阶段最重要的事情，其实不是急着"选赛道"，而是先把编程基础打牢。

比较建议的做法是：先专注于C语言基础学习，跟着C语言群或者课程安排稳扎稳打地学，把变量、函数、数组、指针、结构体、文件、基础算法这些内容学明白。与此同时，OJ题目也要坚持刷，如果能做到200题左右，代码能力和编程思维通常会有比较明显的提升。

在这个过程中，可以开始广泛了解计算机相关的不同方向，比如前端、后端、CTF、嵌入式、视觉算法、游戏开发、Qt、神经网络等。这个阶段的重点不是马上确定"我以后一定做什么"，而是尽量多看、多试、多接触，先知道各个方向大概在学什么、做什么，看看自己真正感兴趣的点在哪里。

如果你在了解之后，逐渐确定自己更适合嵌入式方向，并且已经完成了51单片机或其他基础入门内容，新生天梯赛估计也已经结束，那么到了期末之后，就可以考虑继续往下走了。

寒假阶段可以根据实际情况灵活安排：

- 有实验室寒假集训机会的，优先直接参加集训；
- 没有实验室安排的，可以自费购入一套STM32开发板或套件，在寒假里自学；
- 当然，也完全可以选择先好好休息。忙了一整个学期之后，适当放松并不是什么坏事，不必陷入"寒假必须弯道超车"的焦虑里。

比起某一个假期突击学了多少，长期稳定的学习习惯更重要。

## 大一下：入门STM32，开始真正动手做项目

到了大一下，建议开始系统学习STM32。与此同时，也要持续关注校内硬件实验室的招新信息，尽量争取早一点进入实验室。如果当时还没有合适的实验室在招新，也可以主动联系目标实验室的老师，表达加入意愿，争取获得项目机会或硬件支持。

如果实验室已经有明确的项目安排，那就优先跟着项目走，因为真实项目永远比单纯看教程更能锻炼人。下面说的内容，主要针对"暂时没有实验室安排"的情况。

在这个阶段，推荐直接学习STM32的HAL库。入门资料可以参考RM战队的电控培训内容，它的优点是上手快、比较适合初学者；如果想补充理论，也可以看江科大的课程。需要注意的是，教程可以参考，但代码不要照搬，尤其不要学完HAL之后又回头按标准库的思路机械套代码。尽量自己用HAL库独立实现一遍，这样才能真正把东西学到手。

当基础外设学到一定程度后，不要一直停留在"点灯、串口打印、读ADC"这些零散练习上，最好尽快做一个完整的小项目，把学过的内容串起来。

比较合适的练手项目包括：

- **循迹小车**，这是一个很适合入门的项目，能够把传感器采集、电机驱动、简单控制逻辑、调试排错这些内容都练到，而且5月校电子科技协会举办的星光杯比赛设有循迹组，也正好可以借这个机会实战；
- 如果你觉得循迹车不够有挑战性，也可以尝试**二轮平衡车**，这类项目对PID、传感器融合、控制调试的要求更高，同时还会逼着你接触更多硬件设计、焊接和结构问题；
- 当然，如果你已经有自己特别感兴趣的方向，也完全可以围绕兴趣做别的项目，关键不是项目形式，而是你是否真的亲手把它做出来了。

走到这一步，通常说明你已经具备了一定的独立学习能力。这个时候可以开始更主动地探索自己感兴趣的细分方向，并且在临近暑假时继续关注实验室招新，为后续进入实验室做准备。

## 大二上：进入实验室，在实战中快速成长

如果前面的节奏比较顺，大二上通常已经进入实验室了；如果还没有进入，那也一定要尽快想办法进去。无论是主动联系老师、向学长学姐表达意愿，还是通过项目和比赛证明自己的能力，总之要尽量争取一个真正能做事的平台。

因为到了这个阶段，继续单打独斗虽然也能学，但成长速度往往不如进入实验室后快。实验室最大的价值，不只是提供硬件资源，而是能让你尽早接触真实项目、真实协作和真实比赛。在这种环境下，你学到的不只是某一个技术点，而是"如何把一个东西真正做出来"。

大二上最重要的任务，不再是零散地补教程，而是跟着项目和比赛走。争取参与一个相对完整的项目，最好能从中承担明确模块，比如电机控制、通信协议、算法、RTOS、硬件设计、调试分析等。只有在项目中承担责任，你学到的东西才会真正沉淀下来。

一般来说，一个稍微成体系的创新比赛项目，准备一个学期是很正常的。如果实验室项目本身已经足够饱满，那就先把项目做好；如果项目推进之外还有空余时间，再去系统补文章前面提到的内容，比如软件嵌入式、上位机、算法、通信协议、理论分析这些模块。这个阶段最忌讳的就是"什么都看了一点，什么都没做深"。

## 大二下：开始形成自己的方向，尝试独立承担项目

到了大二下，你通常已经有了一定的知识储备，也经历过至少一轮比较完整的项目实践。这个时候，学习方式应该从"别人安排我做什么"逐步过渡到"我想做什么，我缺什么，就去补什么"。

一方面，你可以更主动地把自己掌握的新技术加到项目里，不再只是被动完成任务。比如你之前只会裸机，现在可以尝试把RTOS引入到项目中；之前只会串口通信，现在可以尝试做Modbus、做MQTT、做Web控制；之前只会调PID，现在可以进一步尝试前馈、状态估计、滤波或运动学模型。这个阶段，技术和项目之间应该开始形成相互促进的关系。

另一方面，如果条件允许，也可以尝试争取实验室老师的支持，做一个相对独立的新项目。这个项目不一定要特别大，但最好能体现出你自己的思考和主导性。因为从"参与别人项目"到"自己推动一个项目"，中间其实跨越了很大一步，这一步对能力提升非常关键。

再往后，暑期基本就会进入电赛准备阶段了。如果你计划打电赛，那么大二下到暑假的这段时间，实际上也是一个重要的过渡期。

## 大三：考研与就业的分水岭

到了大三，很多问题就不能再模糊下去了。你要开始认真思考：自己到底是想考研，还是想直接就业。很多人之所以迟迟做不了决定，不是因为选择太难，而是因为从来没有真正去接触过就业市场，所以对自己的位置没有概念。

这里有一个非常现实、也非常有效的方法：如果你真的不知道自己要不要考研，那就花一段时间认真投简历，试着去找实习。哪怕只是投一个月，你也会很快对自己的水平、项目竞争力、企业需求和就业环境有更直观的认识。很多人原本对就业抱有不切实际的想象，真正开始投递、笔试、面试之后，往往会一下子清醒很多。

- 如果最终决定考研，那大三就要尽快进入复习节奏，把时间安排好；
- 如果不打算考研，或者准备边找工作边看机会，那就一定要尽早准备实习，不要觉得"自己会一点单片机就不愁找工作"。现实情况往往没那么乐观。

找工作从来都不是一件轻松的事，尤其是嵌入式、电控这类方向，对项目质量、实践能力和表达能力都有不低要求。很多人直到真正开始找工作，才发现自己准备得远远不够。所以，不管最后走哪条路，大三都不应该再停留在"随便学点东西"的状态，而应该有更明确的目标感。前面两年积累下来的能力，会在这一阶段真正开始兑现；而这一阶段做出的选择，也会直接影响接下来几年的发展方向。
