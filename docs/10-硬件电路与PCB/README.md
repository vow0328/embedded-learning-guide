# 10. 硬件电路与 PCB

**软件决定系统能做什么，硬件决定系统能不能可靠地做到。**

这一章是硬件方向的主线，但**软件方向的人也应该读一部分**。原因很直接：现实项目中大量"看起来像软件 bug"的问题，根因在硬件。

- 串口收不到数据 → 可能是 TX/RX 接反、没共地、电平不匹配
- ADC 采出来全是噪声 → 可能是参考电压不稳、采样电阻布局不对、地平面被割裂
- 电机一转就复位 → 可能是电源扛不住浪涌
- 系统偶发死机 → 可能是晶振负载电容不对、复位电路设计有问题

**分不清问题出在软件还是硬件，会浪费大量时间在错误的方向上瞎改。** 所以你不需要会做电源、不需要会画高速板，但至少要有"能看懂原理图、会用万用表、能判断问题在哪一侧"的能力。

## 适合谁

- **硬件方向**：全章必读。顺序不必照章节号走，按下面的通读顺序建议来更顺。
- **软件方向**：**强烈建议至少读 10.1、10.2、10.4**。不用精通，但要能看懂、能焊、能量。
- **电机/电源方向**：10.3 和 10.5 是核心。

## 通读顺序建议

```
10.1 电路与电子技术基础  →  会看数据手册（见 12.2）
      ↓
10.2 原理图与 PCB 设计  →  画一块 STM32 最小系统板练手
      ↓
10.4 焊接与返修  →  把上一块板子焊出来、上电、点亮
      ↓
10.6 打样量产与国产替代
      ↓
10.3 电源设计  ← 相对独立的一支，想走电源方向单独深入
      ↓
10.5 信号完整性与 EMC  ← 经验学科，在真实项目里踩坑才会
```

**最好的学习路径是"画一块板 → 焊出来 → 上电点亮"。** 这三个动作串起来，你对硬件系统的理解会从"抽象"变成"具体"。第一次画板大概率有问题，改版是完全正常的事——每改一版，理解都会有实质提升。

## 两个必须养成的习惯

1. **上电前必查电源和地有没有短路。** 用万用表蜂鸣档测一下，几秒钟的事，能救回一块板子和一堆芯片。
2. **第一次给新板子上电时用限流保护。** 带限流功能的可调电源，或者串联一个小功率灯泡。条件不具备时也别直接怼——一块板子烧了是小事，芯片烧了要重新等货期。
