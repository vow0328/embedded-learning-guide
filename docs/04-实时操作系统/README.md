# 4. 实时操作系统

**裸机开发在项目简单时非常高效，但当任务变多、时序变复杂、模块之间需要协调时，它的局限会越来越明显。**

RTOS 存在的意义不是"让代码更高级"，而是解决三个具体问题：**多任务怎么调度、共享资源怎么保护、模块之间怎么通信**。学 RTOS 的重点不是背会多少个 API，而是理解"任务为什么这样划分、资源为什么要这样保护"。

| [4.2 FreeRTOS](02-FreeRTOS.md) | 任务管理与调度机制、信号量/互斥量/队列/事件组/任务通知、时间管理、五种内存方案、中断与 RTOS 配合 | ★★★ |
| [4.3 RT-Thread 与其他 RTOS](03-RT-Thread与其他RTOS.md) | RT-Thread 的设备驱动框架、软件包生态、FinSH 命令行；Zephyr、uCOS 简介；怎么选 | ★★★ |
| [4.4 RTOS 常见问题](04-RTOS常见问题.md) | 优先级反转与优先级继承、死锁、栈溢出的表现与检测、临界区与 `FromISR` API、tick 精度与低功耗冲突、多核 MCU | ★★★★ |

## 适合谁

- **软件方向**：全章必读。
- **电机/控制方向**：4.2 和 4.4 必读——控制任务被意外阻塞是电机项目最常见的诡异故障之一。
- **硬件方向**：可略过，但建议读 4.1 了解软件在忙什么。

## 通读顺序建议

```
4.1 概述  →  4.2 FreeRTOS  →  动手把裸机项目改成多任务
                                    ↓
                          4.4 常见问题（出问题时反复回看）
                                    ↓
                          4.3 RT-Thread（项目变大后再看）
```

**4.4 建议不要一次读完，而是在你的 RTOS 项目出现诡异现象时回来查。** 那里面每一条都是真实踩过的坑。

**关于"要不要上 RTOS"**：能不用的地方就别用。任务数少于 3 个、没有复杂时序协调的项目，裸机结构更简单、更好调试。RTOS 是解决问题的手段，不是能力的象征。
