# 2.2 通讯协议

通讯协议是电控开发里非常重要的一块内容。单片机本身只是"会干活的脑子"，而通讯协议决定了它怎么和传感器、执行器、显示屏、上位机、云平台以及其他设备进行交互。对于电控来说，真正把系统连起来、让模块之间配合起来工作的，靠的就是通讯协议。

通讯协议大致可以分为三类：总线协议、网络通信协议，以及常见的无线通信模块。

学习这部分内容时，不要一开始就去死记概念，最有效的方法是结合具体项目，把协议放到实际场景里去理解。

## 总线协议

| 协议 | 典型应用 | 特点 |
|------|----------|------|
| USART / UART | 调试串口打印、无线模块AT指令通信 | 简单、通用、最适合入门 |
| One-Wire / 单总线 | DHT11、WS2812灯带等 | 线少，但时序要求高 |
| I2C | MPU6050、AHT20、BMP280等传感器 | 接线少，适合多设备挂载 |
| SPI | TFT显示屏、Flash、W5500以太网模块 | 速度快，适合高速外设 |
| CAN | 多节点通信、电机驱动器通信 | 抗干扰强，适合工业场景 |
| RS-485 | 工业长距离多机通信 | 传输远、稳定性好 |

总线协议的学习核心，不是背它们的名字，而是学会看时序图、看数据手册、看通信帧格式。不同协议本质上都是在规定：谁先说、什么时候说、怎么说、说完之后怎么确认。只要把这一套逻辑看懂了，后面不管面对什么新模块，学习速度都会快很多。

### USART / UART

USART是电控开发中最常用、最基础、最值得优先掌握的通讯方式。它最核心的用途有两个：一是作为调试串口，把程序运行状态打印出来，帮助我们排查问题；二是作为外设通信通道，和蓝牙模块、WiFi模块、4G模块、语音模块等进行数据交互。很多无线模块底层都支持AT指令，本质上就是通过串口把命令发给模块，再读取返回结果。

USART学习时要重点掌握波特率、起始位、数据位、停止位、校验位这些基本概念，还要熟悉中断接收、DMA接收、空闲中断、环形缓冲区这些实战中非常常用的技巧。刚开始可以先实现最简单的收发功能，随后逐步升级成DMA + 空闲中断的接收框架，再加上双缓冲区和字符串解析。因为真正的项目里，串口很少只是"发一个字节看灯亮不亮"，更多时候是要稳定接收一整帧数据，并且解析出有意义的信息。

### One-Wire / 单线类协议

单线协议或者说单总线协议，最大的特点就是接线少，但时序要求严格。像DHT11这种温湿度传感器、WS2812灯带这类器件，都属于这一类思路。它们表面看起来简单，实际上对时序控制要求很高，特别适合拿来训练你对波形和延时的理解。

这类协议通常需要你掌握微秒级延时、GPIO输入输出切换、时序判断和波形采样。有些设备虽然只有一根数据线，但实际上传输数据靠的是高低电平持续时间的长短，因此不是"写几个串口函数"就能解决的，而是要对电平时序有比较准确的把控。学习这类协议时，如果能配合逻辑分析仪或者示波器观察波形，理解会非常快。

WS2812这类灯带很适合入门时练手，因为它既有趣，又能直观看到效果，但它也非常容易暴露时序问题。能把这类协议调通，说明你已经开始具备对"时间"和"波形"的基本控制能力了。

### I2C

I2C是非常常见的低速总线协议，特别适合小型传感器和外设。像MPU6050、AHT20、BMP280、OLED显示屏、EEPROM这些常见模块，都大量使用I2C通信。它只需要两根线：SCL和SDA，接线简单，而且同一条总线上可以挂很多设备，因此在传感器场景里非常常见。

I2C学习时，首先要搞清楚主机和从机的概念，理解地址机制、起始信号、停止信号、应答位ACK/NACK这些基本规则。很多新手在I2C上出问题，不是因为代码写得太差，而是因为地址写错、没有上拉电阻、设备没回应ACK，或者总线线太长导致信号不稳定。

I2C是特别适合用来练习"按寄存器读写外设"的协议。很多传感器的使用方式都差不多：先向某个寄存器写入配置，再从某个寄存器读取数据，最后把原始值换算成物理量。这个过程会强迫你去认真看数据手册，也会让你逐步形成"按寄存器思维"来理解外设，这对后面写各种驱动都非常有帮助。

### SPI

SPI是一种速度比较快的同步串行通信协议，常用于对传输速度要求较高的外设。比如TFT彩屏、Flash存储芯片、SD卡、W5500以太网模块等，都经常使用SPI。

SPI的典型信号包括SCLK、MOSI、MISO和CS。它的特点是速度快、通信灵活、全双工，缺点是接线比I2C多，配置也相对更讲究。学习SPI时，必须掌握CPOL和CPHA，也就是常说的SPI模式。很多SPI设备"明明接线没错就是不工作"，问题往往不在硬件，而在模式配错、片选时序不对、或者时钟频率太高导致波形失真。

SPI是一个很适合培养工程调试能力的协议。因为它一旦出问题，表面现象可能很多，但根源常常是模式、时序、片选、速率这些基础问题。学会SPI之后，你对时钟、数据采样边沿和总线时序的理解会明显提升。

### CAN

CAN是工业和汽车电子中非常重要的协议，很多电机控制、机器人底盘、工业控制系统都会用到。它的最大优势是抗干扰能力强，支持多节点通信，而且有优先级仲裁机制，所以在复杂系统里非常稳定。

CAN学习时，需要重点掌握终端电阻、标准帧和扩展帧、数据帧和远程帧、仲裁机制、错误帧以及总线关闭这些知识点。它不是一个适合"点亮一下"就结束的协议，而是越学越能体现工程价值的协议。如果以后想往电机控制、机器人、工业通信方向走，CAN基本属于必学内容。

### RS-485

RS-485更像是一种物理层接口标准，实际项目中常常和Modbus RTU搭配使用。它特别适合工业现场的长距离、多设备通信，比如PLC、变频器、传感器采集、远程仪表等。

RS-485最大的特点是传输距离远、抗干扰能力强、支持多节点，通常以半双工方式工作。学习时要掌握A/B差分线的接法、终端电阻的作用、发送接收方向控制，以及Modbus RTU的基本帧格式和CRC校验。

RS-485很多问题并不复杂，但很容易踩坑，比如A/B接反、没有共地、终端电阻没加、方向控制没处理好。这类问题看上去像软件问题，实际上经常是接线和物理层设计问题，所以学习时一定要养成"先看硬件，再看软件"的习惯。

## 网络通信协议

| 协议 | 特点 | 适用场景 |
|------|------|----------|
| MQTT | 轻量级发布/订阅模型，包头小 | 物联网数据上云、设备控制 |
| HTTP | 请求-响应模型，通用性强 | API调用、网页接口、低频通信 |
| WebSocket | 支持双向实时通信 | 实时监控、网页控制、在线状态推送 |

网络通信协议，通常是从"单片机能跟模块说话"走向"设备能接入互联网"这一步的关键。对于想做物联网方向的同学来说，这部分内容非常重要。

### MQTT

MQTT是物联网里最常用的通信协议之一。它采用发布/订阅模型，不是传统的"你发我收"模式，而是设备把数据发布到某个topic，云平台或客户端订阅这个topic，所有订阅者都可以收到消息。这种方式非常适合传感器数据上报、远程控制、设备状态同步等场景。

MQTT学习时要重点理解Broker、Client、Topic、Publish、Subscribe、QoS这些概念。实际项目里，最常见的流程通常是：STM32通过串口和WiFi模块通信，WiFi模块连接路由器，设备再接入MQTT服务器，向某个topic上报数据，云平台或手机端订阅并显示这些数据，用户再通过云端下发控制指令，设备接收后执行动作。这个链路是很多物联网项目的标准结构，学会它之后，很多实际产品的框架你都会觉得很熟悉。

如果想走物联网方向，MQTT基本属于必须认真掌握的协议。

### HTTP

HTTP是最常见的网络协议之一，特点是结构清晰、调试方便、生态成熟，几乎所有互联网平台都支持。它采用请求—响应的通信模型，适合做API调用、设备配置查询、数据上传、网页接口交互等。

不过HTTP的开销相对较大，不适合高频、实时性特别强的场景。如果只是偶尔上报一次数据、查询一次状态，HTTP很方便；但如果需要持续实时通信，那通常MQTT或WebSocket更合适。

### WebSocket

WebSocket可以理解为在HTTP基础上建立起来的一种持续双向通信机制。它的优势在于连接建立后，客户端和服务器可以长期保持通信，适合做实时刷新、在线监控、远程控制等功能。

如果你的项目中需要做网页端实时显示数据，或者希望网页控制设备时响应尽量快，WebSocket会非常好用。它比HTTP更适合"实时感"较强的应用场景，比如设备状态面板、在线数据曲线、远程控制界面等。

## 无线通信模块

| 类型 | 常用模块 | 特点 |
|------|----------|------|
| WiFi | ESP-01S（ESP8266） | 成本低，常用于联网 |
| 蓝牙 | HC-05、BT24 | 短距离透传、手机控制 |
| LoRa | HC-15等 | 远距离、低功耗 |
| 2.4G | nRF24L01 | 低延迟点对点通信 |
| 4G | ML307、合宙模组 | 广域网接入 |
| NB-IoT | BC26等 | 低功耗广域网 |

很多无线模块本质上都是"串口 + 协议栈 + AT指令"的组合，所以前面提到的USART一定要学扎实。只要串口收发稳定，后面接各种无线模块就会轻松很多。

### WiFi模块

WiFi模块最常见的就是ESP8266和ESP32这一类。它们可以通过AT指令控制，也可以直接开发固件。对于很多项目来说，WiFi模块的核心任务就是：连接路由器、收发数据、接入云平台、和上位机通信。

这类模块最重要的不是"会不会发AT指令"，而是"能不能稳定解析返回的数据"。因为无线模块返回的往往不是单个字节，而是一整段字符串或者帧数据，所以字符串处理能力、缓冲区设计、超时处理这些东西都很关键。实际开发中，推荐用DMA接收加空闲中断，再配合字符串解析和协议帧判断，这样稳定性会高很多。

### 蓝牙模块

蓝牙是非常适合近距离控制的无线方式，常见用途包括手机控制小车、串口透传、设备配网、短距离配置参数等。像HC-05、BT24这类模块，很多项目都用来做手机遥控。

如果你使用的是ESP32，还可以进一步学习BLE配网、蓝牙广播、蓝牙Mesh组网等功能。ESP32的蓝牙能力比较强，既可以做传统蓝牙透传，也可以做低功耗蓝牙设备。在一些简单场景里，还可以通过信号强度RSSI来做粗略距离估算，不过这种方法误差较大，更多是用于辅助判断，不适合高精度定位。如果进一步结合多个节点信号强度，还可以做简单的三点定位，用于室内粗略定位或区域判断。

### LoRa

LoRa是一种远距离、低功耗、低速率的无线通信技术，常见模块有HC-15等。它最大的特点是传输距离远，在空旷环境下可以达到几公里甚至更远，同时功耗很低，非常适合电池供电、长期工作的场景。

学习LoRa时，要重点理解扩频通信的基本概念、频段选择、发射功率、空中速率这些参数，以及收发模式的配置。需要注意的是，LoRa模块的点对点通信和LoRaWAN网络是两个层面的东西：前者是模块之间直接收发，配置简单；后者是一整套组网协议，需要网关和服务器配合，复杂度高很多。入门阶段先从点对点通信练起即可。

### 2.4G

2.4G这一类最常见的模块就是nRF24L01，它工作在2.4GHz频段，主打低延迟、点对点的近距离无线通信。它的特点是响应快、延迟低、成本低，非常适合做小型无线控制系统。nRF24L01的典型应用包括无线遥控、无线手柄、小车遥控、多设备之间的短距离数据传输等。

学习nRF24L01时，需要掌握它的通信信道、地址配置、数据通道、自动应答和重发机制。它本身是通过SPI与单片机通信的，所以在学这个模块之前，最好先把SPI协议掌握好。实际使用中也要注意，2.4G频段比较拥挤（WiFi、蓝牙都在用），在干扰严重的环境下需要合理选择信道来保证通信稳定。

### 4G

4G模块可以让设备直接接入移动网络，不依赖本地的路由器或局域网，因此特别适合那些需要在户外、异地、移动场景下联网的设备。常见的有合宙的ML307等模组，价格已经比较亲民。

使用4G模块需要插入物联网SIM卡，并且要考虑流量资费。开发上，大部分4G模块依然是通过串口AT指令进行控制，完成拨号联网、建立TCP连接、收发数据、接入MQTT等操作。很多模组还集成了相对完整的协议栈，甚至支持直接跑一些联网协议，开发起来比纯底层方便不少。学习时同样要把串口收发和AT指令解析做扎实。

### NB-IoT

NB-IoT是一种低功耗广域网技术，常见模块有BC26等。它的定位和4G不太一样：NB-IoT不追求高速率，而是追求超低功耗、广覆盖、海量连接，特别适合那些只需要偶尔上报少量数据、又要求长时间待机的设备。

学习NB-IoT时，要理解它"低频上报、低功耗待机"的使用模式，以及它通常和运营商网络、物联网平台绑定使用的特点。开发方式同样以串口AT指令为主，重点在于联网、数据上报和功耗管理。需要注意的是，NB-IoT不适合需要频繁、实时、大量传输数据的场景，那不是它擅长的方向。

## 学习建议

通讯协议这一章，不建议只停留在"知道有哪些协议"的层面，而是要真正掌握"怎么用"。最好的学习方式是：协议 + 实物 + 调试工具一起学。

建议的学习顺序是：

1. 先学USART，因为它既是最常用的通信方式，也是调试其他所有无线模块的基础。
2. 再学I2C和SPI，这两个协议最能锻炼你对时序图和底层驱动开发的理解。
3. 然后学CAN和RS-485，这两个协议能让你接触到工业级的稳定性和多机通信逻辑。
4. 最后根据是否要学习物联网方向学MQTT、HTTP、WebSocket以及各种无线模组，去理解如何将本地数据推向云端，实现真正的物联网。

另外要提前说明一点：通讯协议覆盖面很广，目前也没有一套真正适合所有电控同学、从头到尾完整覆盖全部协议的优质教学视频合集。实际情况往往是，大多数人也不会把所有协议都系统学完，而是根据项目需要逐步补。换句话说，学到哪一块内容，就有针对性地去搜那一块的教程和资料，这才是更现实、也更高效的方式。

## 小节总结

通讯协议是电控开发中的核心基础之一，它决定了单片机如何与外部世界交换数据，也是从"能点灯"走向"能做系统"的关键一步。

对于入门阶段来说，建议先从USART、I2C、SPI这三类最常用的总线协议学起，重点掌握时序图、寄存器读写、数据解析和调试方法；在此基础上，再逐步学习CAN、RS-485这些更偏工程应用的协议，以及MQTT、HTTP、WebSocket这些网络通信协议。

学习通讯协议时，建议尽量准备串口调试助手、逻辑分析仪、示波器、万用表这些基础工具。逻辑分析仪尤其值得推荐，价格不高，但对看串口、I2C、SPI的波序特别有帮助。很多代码看起来没问题、实际上通信失败的情况，用逻辑分析仪一看就能定位到是起始位错了还是应答位没收到。

如果你接触无线模块较多，建议尽早建立一套稳定的串口收发框架，比如DMA接收 + 空闲中断 + 环形缓冲区 + 异步解析。这套东西一旦搭起来，后面你接任何模块（无论是WiFi、蓝牙还是4G）都会轻松很多，不再会因为数据丢包或卡死而烦恼。

如果你想走物联网方向，重点要放在串口收发、AT指令、MQTT协议和数据解析上；如果你想走工业控制或机器人方向，就要更重视CAN、RS-485和总线稳定性设计。无线模块的选择则要根据距离、功耗、带宽这三个维度进行权衡。
