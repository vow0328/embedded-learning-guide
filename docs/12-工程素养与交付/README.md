# 12. 工程素养与交付

**这一章的内容不会让你多会一个技术点，但它决定了你能不能被委以责任、能不能独立负责一个项目。**

技术能力让你"能做出来"，工程素养让你"做出来的东西能交付、能维护、能被信任"。在企业里，很多时候这些能力属于默认要求，而不是加分项。

## 适合谁

- **所有人**：**12.2 是全章、甚至整份教程里最被低估的一篇**，建议无论什么方向都读。
- **求职者**：12.1 和 12.2 是面试中区分"学过"和"做过"的地方。
- **在职工程师**：12.3、12.4、12.5 是往主导项目方向走必须补的。
- **汽车电子/医疗设备方向**：12.4 必读。

## 通读顺序建议

```
12.2 数据手册阅读方法  ← 先读这篇，它是所有技术能力的乘数
      ↓
12.1 需求分析与方案选型
      ↓
12.3 文档、评审与版本发布
      ↓
12.5 生产交付与 BOM 管理
      ↓
12.4 功能安全与可靠性（按行业需要）
```

## 为什么 12.2 排在最前面

**会读数据手册，是嵌入式工程师的第一元技能。**

原因很简单：这一行所有的技术细节，最终的权威来源都是数据手册。教程会过时、视频会讲错、AI 会编造，但数据手册是芯片厂商的正式承诺。

一个会读数据手册的人，面对一颗从没用过的芯片，能在一两个小时内跑通它；不会读的人，只能到处搜例程，搜不到就卡住。

**更关键的是**：面试时如果被问到"这个参数你是怎么确定的"，回答"我查了数据手册第 X 页的电气特性表"和回答"我看别人代码里是这么写的"，是两个量级的差距。
