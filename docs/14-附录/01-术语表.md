# 14.1 术语表

> **前置知识**：无
>
> **掌握标准**：读到不认识的缩写时知道去哪查，并理解这些术语在嵌入式语境下的准确含义
>
> **对应岗位**：全部
>
> **练手建议**：无

这份表不是词典。它只收录本教程中出现过的、并且**容易混淆或者容易望文生义**的术语——真正一眼就懂的词（比如"电阻""函数"）不在这里。

用法是查，不是背。读到某个缩写不认识，回来翻一下，看完就走。很多术语第一次出现的地方有更详细的讲解，所以每一组下面都给了对应篇目的链接，想深挖直接点过去。

需要提醒的是：**嵌入式行业里的术语是以英文缩写为主流通行的**，面试时说"串行外设接口"对方可能反应不过来，说 SPI 反而最清楚。所以这里的条目凡是行业里有通用英文缩写的，都给出中文名和英文缩写，但你要记住的是英文那一半。

### 一、芯片与体系结构

详见 [2.1 单片机平台选型](../02-MCU与体系结构/01-单片机平台选型.md)、[2.2 Cortex-M 内核与启动流程](../02-MCU与体系结构/02-Cortex-M内核与启动流程.md)。

- **单片机（MCU，Microcontroller Unit）**：把 CPU、Flash、SRAM、各种外设集成在一颗芯片上的完整计算机。本教程统一用"单片机"，不要写成"微控制器"。
- **微处理器（MPU，Microprocessor Unit）**：通常指只有 CPU 核心、需要外挂内存和存储才能工作的芯片，比如跑 Linux 的那类。注意它和"内存保护单元"的缩写撞车了，看到 MPU 先看上下文。
- **内存保护单元（MPU，Memory Protection Unit）**：Cortex-M 上可选的一块硬件，用来给内存分区设置访问权限，防止野指针踩到别人的区域。它只做权限检查，不做地址翻译——这是它和 MMU 最本质的区别。
- **内存管理单元（MMU，Memory Management Unit）**：做虚拟地址到物理地址的翻译，是 Linux 能跑起来的前提。Cortex-M 一般没有 MMU，Cortex-A 一定有。**MPU 管权限，MMU 管翻译**，这是面试常问的一对。
- **片上系统（SoC，System on Chip）**：比单片机集成度更高，往往包含多核 CPU、GPU、NPU、DDR 控制器等。很多所谓"单片机"其实是 SoC，边界已经模糊了。
- **芯片内核（Core）**：CPU 核本身，比如 Cortex-M4、Cortex-M7。**内核不等于架构**——Cortex-M4 是内核，它实现的是 ARMv7E-M 架构，日常说的"Cortex-M4 架构"是句口误。同一颗芯片型号里经常有不同内核的版本，选型时容易看漏。
- **ARM**：一家公司，也是一种处理器指令集架构和它的授权模式。ARM 公司自己不卖芯片，只卖设计授权，所以 ST、GD、NXP 的芯片可以都是 ARM 内核。
- **Cortex-M / Cortex-A / Cortex-R**：ARM 的三条产品线。M 面向单片机，实时性好、无 MMU；A 面向应用处理器，性能强、跑 Linux；R 面向高可靠实时，常用在汽车和工业。选型时选错系列基本等于推倒重来。
- **指令集架构（ISA，Instruction Set Architecture）与 ARMv6-M / ARMv7-M / ARMv7E-M / ARMv8-M**：Cortex-M 各内核各自实现的架构版本。M0 与 M0+ 是 ARMv6-M，M3 是 ARMv7-M，M4 与 M7 是 ARMv7E-M（E 指带 DSP 指令），M33 是 ARMv8-M，M55 是 ARMv8.1-M。**它决定你能用哪些指令**：M0 上没有 FPU、没有 DSP 指令、也没有硬件除法，因为这些东西在 ARMv6-M 里根本不存在；TrustZone 则是 ARMv8-M 才引入的。对比内核时真正要比的是这一代架构。
- **RISC-V**：开源指令集架构，不需要授权费。生态还在成长，国产芯片里用得越来越多，但工具链和资料成熟度不如 ARM。
- **浮点单元（FPU，Floating Point Unit）**：硬件做浮点运算的模块。没有 FPU 的内核（比如 Cortex-M0）做一次浮点乘法要几十个周期，**这是"你的芯片跑不跑得动 FOC"的关键前提之一**。
- **数字信号处理指令（DSP 指令）**：Cortex-M4/M7 上的一批乘加类指令，做滤波和变换时能快好几倍。它不是独立的 DSP 芯片。
- **内核外设与片上外设**：Cortex-M 把 NVIC、SysTick、SCB、MPU、ITM 这些归到内核，叫内核外设（core peripheral），挂在私有外设总线（PPB，Private Peripheral Bus）上，地址由 ARM 定死、各家芯片一致；厂商自己集成的 GPIO、USART、TIM、ADC 叫片上外设，在 0x4000_0000 起的外设区，地址和数量各家不同。**"这个寄存器该查哪本手册"的困惑多半来自这条分界**：内核外设查 ARM 的架构手册，片上外设查厂商的参考手册。
- **嵌套向量中断控制器（NVIC，Nested Vectored Interrupt Controller）**：Cortex-M 的内核外设之一，统一的中断控制器。所有外设中断都归它管，所以它的配置方式和别家芯片不一样。
- **中断向量表（Vector Table）**：一块固定格式的表，每一项存一个异常或中断的处理函数入口地址。表的前两项特殊：第一项是初始 MSP，第二项是复位向量。
- **向量表偏移寄存器（VTOR，Vector Table Offset Register）**：用来把向量表搬到别的位置，做 Bootloader 跳转时必须配它，否则跳过去之后中断全乱。**这是 IAP 升级里最常被漏掉的一步。**
- **主栈指针（MSP）与进程栈指针（PSP）**：Cortex-M 的两个栈指针。MSP 给中断和内核用，PSP 给任务用；裸机一般只用 MSP，上了 RTOS 才会两个都用起来。寄存器的名字是 R13，只是一个指针的两个影子。
- **特权级与操作模式**：Cortex-M 分特权级和用户级、线程模式和处理器模式。裸机开发基本感觉不到它，写 RTOS 或跑 Linux 才必须搞懂。
- **位带操作（Bit-Banding）**：Cortex-M3/M4 的一个特性，能把某个比特映射成一个独立地址，实现原子性的位读写。老教程爱讲，新芯片上很多已经不支持了，注意别被过时教程误导。
- **系统节拍定时器（SysTick）**：内核外设，24 位递减定时器，寄存器固定在 PPB 区的 0xE000_E010，RTOS 的心跳一般就靠它。它和厂商在片上外设区提供的定时器（TIM 那类）不是一回事：不需要开 RCC 时钟，异常号固定是 15，属于系统异常而不是外设中断。
- **AHB 与 APB**：两条片上总线。AHB 快，挂内核、DMA、高速外设；APB 慢，挂串口、定时器这类外设。看到外设时钟使能分布在两个总线上，原因就在这里。
- **总线矩阵（Bus Matrix）**：把多条主设备（内核、DMA）和多条从设备（Flash、SRAM、外设）互相连起来的交换网络，让它们能并行访问。DMA 搬运时内核还能同时跑代码，靠的就是它。
- **时钟树（Clock Tree）**：从晶振或内部时钟源出发，经过分频、倍频、锁相环，最后分到各个外设的一整套结构。**外设"配好了不工作"，一半原因是忘了开它的时钟。**
- **启动文件（Startup File）**：汇编写的一段代码，负责初始化栈指针、把中断向量表放好、把 .data 从 Flash 搬到 SRAM、把 .bss 清零，最后跳到 main。它是芯片厂商给的，不是编译器生成的。
- **Boot ROM**：芯片内部固化的启动代码，负责最基本的上电检查和启动模式选择，有些芯片还提供内置的串口下载功能（ISP 就靠它）。
- **ISP / IAP / ICP**：三个容易混的升级方式。ISP 靠芯片内置的 Boot ROM 和上位机工具下载，芯片必须停在被引导状态；IAP 是用户程序自己写 Flash，实现真正的在线升级；ICP 是"在电路编程"，靠调试口直接烧，产线上最常用。**IAP 是你自己写的，ISP 是芯片厂商给的。**
- **芯片勘误（Errata）**：厂商公布的一个清单，列出这颗芯片"数据手册说了但实际做不到"的地方。**踩坑踩到怀疑人生时，第一件事是去翻勘误表。**

### 二、存储与内存

详见 [2.5 Flash 存储与参数管理](../02-MCU与体系结构/05-Flash存储与参数管理.md)。

- **闪存（Flash）**：单片机上的程序存储区。关键特性是**读写可以按字节来，擦除却只能整块（通常按扇区）进行**——想改一个字节，得把整个扇区读出来、擦掉、再写回去。参数存储的所有设计思路都是被这一条逼出来的。
- **电可擦除可编程只读存储器（EEPROM）**：可以按字节擦写的非易失存储，寿命比 Flash 长得多。很多单片机没有片内 EEPROM，需要用 Flash 模拟。
- **静态随机存储器（SRAM）**：掉电即失的运行时内存，栈、堆、全局变量都在这。**注意"栈"其实是一个指针，它指向的那块内存往往就在 SRAM 的开头或结尾，而且被链接脚本固定住了——所以它是指针，但也是布局的一部分。**
- **动态随机存储器（DRAM）与 SDRAM**：需要不断刷新才能保住数据的内存，容量大、价格低，嵌入式里基本只在跑 Linux 的板子上出现。DDR 是它的高速版本。
- **缓存（Cache）**：CPU 和主存之间的高速缓冲，用来掩盖主存延迟。**在 ARM + FPGA 的异构系统里，Cache 是最著名的坑：FPGA 看到的是一份内存，ARM 看到的是缓存里那份旧的。** 这类系统里必须显式做缓存维护，否则数据对不上。
- **直接存储器访问（DMA，Direct Memory Access）**：让外设绕过 CPU 直接搬运数据。用它的代价是**缓存一致性**和**搬运期间的缓冲区不可访问**，这两条是 DMA 相关 bug 的主要来源。
- **栈（Stack）与堆（Heap）**：栈由编译器自动管理，存局部变量和函数返回地址，向下生长；堆由你自己申请释放，向上生长。两者**相向生长，撞上就是栈溢出或堆溢出**，而且这类问题的表现往往离现场很远。
- **.text / .data / .bss**：编译产物里的三个段。.text 是代码，烧在 Flash 里原地执行；.data 是有初值的全局变量，初值存在 Flash、运行时拷到 SRAM；.bss 是无初值的全局变量，只占 SRAM 且要清零。**这是"内存分几段"那道面试题的标准答案。**
- **链接脚本（Linker Script）**：告诉链接器"哪块内存放什么"的配置文件。改程序起始地址、划分 Bootloader 和 APP 的分界、加一段"不初始化"的内存，全都要动它。
- **map 文件**：链接器生成的清单，列出每个符号最终落在哪个地址、每个段占多少空间。**排查内存不够、栈溢出、链接报错时，它是第一手证据。**
- **内存池（Memory Pool）**：预先分配好的一批固定大小内存块。嵌入式不用 malloc 的原因之一是碎片化不可控，内存池用"浪费一点空间"换"分配时间确定"。
- **磨损均衡（Wear Leveling）**：Flash 每个扇区擦写次数有限，把写操作轮流分散到不同扇区去，延长整体寿命。用 Flash 模拟 EEPROM 时必须做。
- **掉电保护**：在写参数的中途断电，数据可能只写了一半。做法一般是双备份加标志位加校验，用一个小区域记录"这次写入是否完成"。
- **内存映射（Memory Mapping）**：单片机上外设寄存器和内存共用同一套地址空间，所以读写寄存器就像读写变量。**这是 Cortex-M 的设计哲学，也是"指针能直接指向寄存器"的原因。**
- **大小端（Endianness）**：多字节数据在内存里的存放顺序。ARM 通常是小端，但**很多通信协议和文件格式规定用大端**（网络字节序就是大端），而 CAN、Modbus 这类常用的工业协议反而是小端——**两边的默认不一致，正是协议解析错误最常见的来源。** 收发多字节数据之前，先确认协议是怎么规定的。

### 三、外设与接口

详见 [2.3 通用外设](../02-MCU与体系结构/03-通用外设.md)、[2.4 中断系统与低功耗](../02-MCU与体系结构/04-中断系统与低功耗.md)。

- **通用输入输出（GPIO）**：最基础的外设。常见的坑是忘了配时钟、配了方向没配上下拉、复用功能没选对。
- **开漏输出与上拉电阻**：开漏只能拉低不能拉高，必须外加上拉电阻才能出现高电平。I2C 必须用开漏，因为一根线上挂多个器件，推挽输出会直接短路打架。
- **外部中断（EXTI）**：把某个引脚的电平跳变变成中断。注意消抖——按键接 EXTI 而不做消抖，一次按下会触发一串中断。
- **定时器（TIM）**：比想象中复杂得多。除了定时，还能做输入捕获、输出比较、编码器接口、PWM 输出，是性价比最高的外设。
- **脉宽调制（PWM，Pulse Width Modulation）**：用占空比等效出模拟量。调电机速度、调 LED 亮度、控制舵机角度，全靠它。
- **模数转换器（ADC）**：把模拟电压变成数字量。**工程上真正的难点从来不是配置，而是参考电压稳不稳、采样时间够不够、地平面有没有被割裂。**
- **数模转换器（DAC）**：反过来，把数字量变成电压。很多单片机没有，或者只有一个通道。
- **规则组与注入组**：STM32 的 ADC 有两套通道序列。规则组是常规轮询，注入组可以打断规则组、插队转换。**注入组的存在意义就是"在 PWM 中点精确采一次电流"，这是 FOC 电流采样的关键机制。**
- **比较器（COMP）**：把两个模拟电压比大小，输出高低电平。过流保护用它比用软件判快得多。
- **运算放大器（运放）**：模拟信号调理的核心器件。电机电流采样、传感器信号放大基本都要经过它。
- **看门狗（Watchdog）**：程序跑飞时把芯片复位。用它最大的坑是**在中断里喂狗**——主循环卡死了但中断还在跑，狗照喂，复位不了，等于没装。
- **独立看门狗与窗口看门狗**：独立看门狗只要求"别太久不喂"，窗口看门狗的喂狗时间还有一个下限——喂太早也算错。**窗口看门狗防的是"程序跑飞后在错误的时机乱喂"，比独立看门狗更难骗过。**
- **实时时钟（RTC，Real-Time Clock）**：靠独立晶振和电池维持的日历时钟，主电源断了也能走。注意它和"实时"（Real-Time）这个词没关系，只是名字撞了。
- **循环冗余校验外设（CRC 外设）**：硬件算 CRC，比软件快得多。固件校验和通信校验都用得上。
- **中断服务函数（ISR，Interrupt Service Routine）**：中断发生时执行的函数。三条铁律：**尽量短、不要阻塞、不要调可能阻塞的接口。**
- **临界区（Critical Section）**：一段不能被中断打断的代码。原则是"能不开中断就别开"，因为它直接影响中断延迟。
- **低功耗模式（睡眠 / 停止 / 待机）**：三种依次更省电、也更难唤醒的模式。待机模式基本等于重新上电，唤醒后程序从头开始，别以为是接着跑。
- **唤醒源（Wake-up Source）**：能把芯片从低功耗模式叫醒的事件。**配了低功耗却没配唤醒源，芯片就叫不醒了**——这是新手最常见的低功耗事故。

### 四、通信协议

详见 [7.1 总线协议](../07-通信与物联网/01-总线协议.md)、[7.2 网络与应用层协议](../07-通信与物联网/02-网络与应用层协议.md)。

- **通用异步收发器（UART）**：最基础也最该先学的串口。所谓"异步"是指没有时钟线，靠约定的波特率对齐，所以两边必须配成一样，稍微偏一点就收错。
- **通用同步异步收发器（USART）**：比 UART 多一个同步模式，可以输出时钟线。**日常说的"串口"其实都是 UART 模式，这两者在单片机上是同一个外设的两种用法，不用当成两个东西学。**
- **TTL / RS-232 / RS-485**：三种电气层标准，解决的是"用什么电压表示 0 和 1"以及"能传多远"。**它们和 UART 不是并列关系**——UART 是数据格式，这三者是物理层。所以"RS-485 转 TTL 模块"才是正确的说法。
- **单端与差分**：单端信号一根线对地传，容易受干扰；差分信号两根线传一对反相信号，接收端看两者的差，共模干扰被抵消。**RS-232 是单端，RS-485 和 CAN 是差分**，这就是后者能跑上百米、前者只能跑几米的原因。
- **共地**：两个设备之间必须有共同的参考地，否则电平没有意义。**串口不通时，先查 TX/RX 有没有接反、有没有共地、电平是否匹配——这三条能解决大半问题。**
- **波特率与比特率**：波特率是"每秒多少个码元"，比特率是"每秒多少个比特"。串口里一个码元恰好承载一个比特，所以两个数相等，日常可以混用；但在别的调制方式下它们不等，严格说不该混。
- **流控（Flow Control）**：防止发得比收得快。硬件流控用 RTS/CTS 两根线，软件流控用特殊字符。**没人用的原因很实际：多两根线，而且软件流控的转义处理容易出错。**
- **半双工与全双工**：半双工同一时刻只能一个方向传（RS-485），全双工可以同时收发（RS-232、SPI）。**半双工最大的坑是收发切换的时序**：发完到收之间必须留够时间，切早了会把自己的回声当成数据。
- **主从（Master-Slave）**：一个主设备发命令，从设备只应答。I2C、Modbus、SPI 都是这个模型，好处是不会冲突，坏处是从设备不能主动上报。
- **单总线（1-Wire）**：只用一根数据线通信的总线形式。**"单总线"说的是线少，不决定双工方式**，DHT11、WS2812 也常被归到这一类。线少，但**时序要求非常严**，中断一多就容易读失败。
- **集成电路总线（I2C）**：两根线挂一堆器件，靠地址区分。必须开漏加上拉，上拉电阻要按总线电容算，不是随便找个 4.7k 就行。
- **时钟拉伸与总线仲裁**：I2C 的两个高级机制。时钟拉伸是从设备拉低时钟线要求主设备等一等；总线仲裁是多个主设备同时发时靠逐位比较决定谁赢。**用不到的东西，但面试爱问。**
- **串行外设接口（SPI）**：速度快，代价是引脚多。**CPOL 和 CPHA 是它最容易配错的地方**——这两个参数配错，波形看着完全正常但数据全错。
- **片选与菊花链**：片选是给每个从设备一根线；菊花链把所有设备串起来，只用一根片选。菊花链省引脚，但一个坏了全断。
- **控制器局域网（CAN）**：多节点系统的事实标准，汽车和工业都用它。差分传输、有仲裁机制、抗干扰强。
- **报文 ID 与优先级**：CAN 的 ID 不只是标识符，**ID 数值越小优先级越高**，仲裁时靠它决定谁先发。所以 ID 分配是一种设计决策，不是随便编的。
- **位定时与采样点**：CAN 把一个比特分成若干时间份额，采样点决定在哪个位置读电平。**采样点配错，短线上没事，线一长就随机报错。**
- **终端电阻**：CAN 和 RS-485 总线两端必须各接一个 120 欧姆电阻，用来消除反射。**少接一个，短线上可能还能跑，线一长就间歇性出错**——这类问题最难查。
- **CAN FD**：CAN 的升级版，数据段可以变长、速率可以提高。**注意它的数据段和仲裁段波特率不同**，配置时容易只配一个。
- **局部互联网络（LIN）与 I2S**：LIN 是汽车里的低成本低速总线，常用来带车窗、雨刷这类不重要的节点；I2S 是音频专用的数字接口，和 I2C 名字像但完全无关。
- **Modbus**：工业最主流的应用层协议，分 RTU（走串口）和 TCP（走以太网）两种。它规定的四张寄存器表和功能码是整个工业设备互通的共同语言。
- **功能码与寄存器模型**：Modbus 把设备的数据抽象成四类寄存器（线圈、离散输入、保持寄存器、输入寄存器），用功能码去读写。**搞懂这套模型，任何 Modbus 设备都能上手。**
- **CANopen 与 UDS 与 AUTOSAR**：汽车电子的三套上层规范。CANopen 是工业运动控制常用的 CAN 应用层；UDS 是诊断协议，接诊断仪读故障码用的——**这两个跑在 CAN 之上，不是替代 CAN**。AUTOSAR 则是另一回事：它是一整套分层软件架构标准，**屏蔽掉的是"这个信号走 CAN 还是走以太网"这类细节**，CAN 只是它支持的总线之一。
- **传输控制协议与用户数据报协议（TCP / UDP）**：TCP 保证可靠有序，代价是延迟和开销；UDP 不保证，但快。**选择依据不是"哪个好"，而是"丢一包要不要重传"**：视频流丢一包无所谓，控制指令丢了就得出事。
- **套接字（Socket）**：操作系统给网络通信提供的接口。嵌入式 Linux 上写网络程序，就是围绕它的一堆函数调用。
- **消息队列遥测传输（MQTT）**：物联网最主流的协议。三个要记住的概念：Topic 是消息主题（支持通配符）、QoS 是三个可靠性等级（等级越高开销越大）、保活是心跳机制（不发包连接会被踢）。
- **超文本传输协议与 WebSocket（HTTP / WebSocket）**：HTTP 是请求-应答模型，适合"偶尔上报一次"；WebSocket 是全双工长连接，适合"服务器要主动推给你"。嵌入式上 HTTP 还能用，但别指望它做实时推送。
- **受约束应用协议（CoAP）**：为资源极度受限的设备设计的协议，基于 UDP，比 MQTT 更轻。国内实际项目里用得少，但理念值得了解。
- **轻量 IP 协议栈与 cJSON（LwIP / cJSON）**：两个嵌入式常用中间件。LwIP 是精简版 TCP/IP 协议栈，cJSON 是超轻量的 JSON 解析库。**它们的价值就是"能塞进单片机的内存里"。**
- **无线保真（Wi-Fi）与蓝牙低功耗（BLE）**：Wi-Fi 带宽大功耗大，适合有电源的场合；BLE 功耗极低，适合电池设备。**BLE 不是"蓝牙的简化版"，而是另一套协议栈**，别把经典蓝牙的经验直接套上去。
- **远距离无线电（LoRa）与窄带物联网（NB-IoT）**：LoRa 是免授权的自组网方案，适合自己建网关的场景；NB-IoT 走运营商网络，适合广域覆盖但需要流量卡。选型看的是"你有没有自己的网关"。
- **AT 指令**：模块厂商提供的文本命令接口。**几乎所有无线模块都走这条路**，所以搭一套通用的 AT 命令解析框架，比每个模块写一遍划算得多。
- **物模型与设备鉴权**：云平台的接入概念。物模型是把你设备的能力用统一格式描述出来，鉴权是证明"这个设备是合法注册的"。
- **安全启动与固件签名**：启动时先验证固件签名再运行，防止固件被篡改。**只在链路加密不够，攻击者可以刷一个假固件进来。**
- **对称加密、非对称加密与哈希**：对称加密一个密钥加解密，快；非对称加密公钥私钥配对，慢但能解决密钥分发；哈希是单向摘要，用来校验完整性。**固件签名用的是哈希加非对称加密的组合。**
- **防抄板**：防止别人直接复制你的硬件和固件。常见手段是芯片读保护、加密芯片、唯一 ID 绑定。**说实话，只要成本够高就能破，所以目标是把抄板成本抬到不划算，而不是做到绝对安全。**

### 五、实时操作系统

详见 [4.1 RTOS 概述与裸机局限](../04-实时操作系统/01-RTOS概述与裸机局限.md)、[4.4 RTOS 常见问题](../04-实时操作系统/04-RTOS常见问题.md)。

- **实时操作系统（RTOS，Real-Time Operating System）**：本教程统一写"实时操作系统（RTOS）"，不要写"RTOS 系统"。
- **裸机（Bare Metal）**：没有操作系统，一个 main 循环加若干中断。**不是落后的代名词**，任务少于三个、没有复杂时序协调的项目，裸机更简单也更好调试。
- **前后台架构**：裸机最常见的结构——中断（前台）负责响应事件，main 循环（后台）负责处理。**它的固有缺陷是后台任务的响应时间不可预测**，一件事做久了，其他事全被拖住。
- **任务（Task）与线程（Thread）**：RTOS 里可以独立调度的一段执行流。每个任务有自己的栈，所以**任务数越多，RAM 消耗越大**——这是上 RTOS 的第一笔成本。
- **调度器（Scheduler）**：决定"下一个该谁跑"的那段代码。它的策略直接决定了系统的实时性表现。
- **抢占式与协作式调度**：抢占式是高优先级任务就绪就立刻切过去；协作式必须等当前任务主动让出。**RTOS 基本都是抢占式**，协作式在现代项目里几乎见不到。
- **优先级反转（Priority Inversion）**：高优先级任务等一个被低优先级任务持有的锁，而低优先级任务又被中优先级任务抢了 CPU，结果高优先级任务被无限期拖住。**这是 RTOS 里最阴险的一类问题，因为它只在特定的时序下偶发。**
- **优先级继承（Priority Inheritance）**：解决优先级反转的机制——低优先级任务拿到锁时临时提升到高优先级，让它赶紧跑完释放锁。**所以共享资源要用互斥量而不是二值信号量。**
- **互斥量、信号量、队列、事件组、任务通知**：RTOS 的五种通信与同步手段。记忆方式是记场景：互斥量保护共享资源（带优先级继承），信号量做同步或计数（不带继承），队列传数据，事件组等"多个条件都满足"，任务通知最省资源但只能一对一。
- **上下文切换（Context Switch）**：保存当前任务的寄存器现场、恢复下一个任务的现场。它是有开销的，**切得太频繁会白白吃掉 CPU**。
- **高水位线（Stack High Water Mark）**：记录任务栈曾经用到的最深位置，也叫栈高水位线。**上 RTOS 后第一件事就是定期打印所有任务的高水位线**，留 20%~30% 余量才算安全。
- **系统节拍（Tick）**：RTOS 的时间基准，通常是 SysTick 产生的周期性中断。**Tick 频率决定了最小延时精度，也决定了每次 Tick 都要花的开销**——这就是低功耗和实时性的矛盾所在。
- **软实时与硬实时**：软实时允许偶尔超时（比如视频播放，卡一下能忍），硬实时一次超时就等于失败（比如电机换相、安全气囊）。**大多数嵌入式项目是软实时，别被"实时"两个字吓住。**
- **死锁（Deadlock）**：两个任务各持一把锁、又都在等对方那把。避免的办法是统一加锁顺序，或者用带超时的获取。

### 六、电机与控制

详见 [6.1 电机基础与选型](../06-电机与执行器/01-电机基础与选型.md)、[6.3 电机控制算法](../06-电机与执行器/03-电机控制算法.md)、[6.4 位置与电流检测](../06-电机与执行器/04-位置与电流检测.md)。

- **有刷电机**：靠机械换向器和电刷换相，驱动最简单（给电就转、反接就反），但**电刷会磨损、会产生电火花**，寿命和电磁干扰都不如无刷。
- **无刷直流电机（BLDC，Brushless DC Motor）**：没有电刷，靠电子换相。反电动势接近梯形波，控制上常用六步换相。
- **永磁同步电机（PMSM）**：和 BLDC 结构相似，但反电动势是正弦波，控制上配 FOC。**BLDC 和 PMSM 的区别主要看反电动势波形，不是看外形**，很多场合两者混着叫。
- **步进电机**：给一个脉冲走一步，开环就能定位。代价是会丢步且丢步不自知——所以要闭环步进。
- **舵机与总线舵机**：舵机内置控制电路，给 PWM 就给角度；总线舵机把 PWM 换成串行总线，可以读回角度、串联多个。
- **H 桥与半桥**：H 桥用四个开关管控制一个有刷电机的正反转；半桥是三相逆变的一相。**H 桥的经典事故是上下管直通，一通电就炸。**
- **三相逆变**：三个半桥组成，把直流变成三相交流驱动无刷电机。母线电容、死区、自举电路都在这一块。
- **金属氧化物半导体场效应管（MOSFET）与栅极驱动与自举**：MOSFET 是功率开关，栅极驱动负责把它快速打开关断，自举电路负责给高边开关管提供高于母线的驱动电压。**自举电容选错，表现是"高边管发烫"，而不是明显的不工作。**
- **死区与直通**：同一桥臂上下两个管子不能同时导通，所以驱动信号之间要插入一段"都关断"的时间，这就是死区。**死区是必须的，但它会带来输出电压误差**，低速时表现为转矩脉动。
- **死区补偿**：根据电流方向把死区造成的电压损失补回来。**电机低速抖动、转矩脉动大，先查死区补偿做了没有。**
- **母线电容**：跨接在电源和逆变桥之间的储能电容，负责吸收换相时的电流突变。**"电机一转就复位"，根因经常是母线电容不够或者电源限流。**
- **极对数与 KV 值**：极对数决定电角度和机械角度的倍数关系；KV 值是每伏特对应的空载转速。**选型时这两个参数看错，整套控制参数都得重算。**
- **减速器与传动比**：减速器降低转速、放大扭矩，同时也把电机的机械角度换算成输出轴角度。**编码器装在哪一侧，算的是哪个角度，必须一开始就明确。**
- **换相**：无刷电机没有电刷，必须根据转子位置依次切换通电相。**"为什么无刷电机需要换相"是理解电机控制的第一道门。**
- **六步换相**：最基础的换相方式，每 60 度电角度换一次，一次两相通电。**简单、能转，但转矩脉动大**——先用它把电机转起来，再考虑上 FOC。
- **磁场定向控制（FOC，Field-Oriented Control）**：把三相交流量通过坐标变换变成两个直流量分别控制，从而像控制有刷电机一样控制无刷电机。它是"把交流问题变成直流问题"。
- **Clarke 变换与 Park 变换**：FOC 的两步坐标变换。Clarke 把三相变成两相静止坐标，Park 再把它转到跟着转子转的坐标系。**名字看晕不要紧，记住第一步降维、第二步跟着转子转就够了。**
- **dq 轴**：Park 变换后的两个轴。d 轴是磁场方向，i d 一般控成 0（表贴式电机）；q 轴是转矩方向，i q 决定出力。**所以 FOC 的核心就是"控制 i d 等于 0，再控制 i q"。**
- **空间矢量脉宽调制（SVPWM）与正弦脉宽调制（SPWM）**：把 dq 电压变成六个开关管的开关信号的两种方式。SVPWM 电压利用率更高，是现在的主流。
- **电角度与机械角度**：电角度等于机械角度乘以极对数。**这是电机控制里最经典的一对混淆点**：霍尔和编码器给的是机械角度，Park 变换要的是电角度，中间那个乘极对数的步骤漏了，电机就会转得异常。
- **霍尔传感器与换相表**：霍尔给的是离散的转子位置区间（六步换相对应六个状态），根据它查表决定给哪两相通电。
- **增量式编码器与绝对式编码器**：增量式输出脉冲，只能知道"转了多少"，上电时不知道绝对位置，需要找零；绝对式上电就知道位置，但接口更复杂、价格更高。
- **正交解码与四倍频**：编码器的 A、B 两相相位差 90 度，硬件正交解码可以同时得到方向和计数；对 A、B 的上升沿下降沿都计数，就把分辨率提高到四倍——**这是"免费提高分辨率"的技巧**。
- **旋转变压器（旋变）**：一种靠电磁耦合测角度的器件，耐高温、抗振动，常用于汽车和工业伺服。**输出是模拟信号，需要专门的解码芯片。**
- **磁编码器**：靠检测磁场变化测角度，体积小、成本低，近年在中低端场合大量替代光电编码器。
- **无感与有感**：有感是有位置传感器（霍尔或编码器），无感是靠反电动势或电流估算转子位置。**无感能省掉传感器和线，但低速和零速时估算不可靠**——所以"无感启动"是一道独立的难题。
- **观测器与滑模观测器**：无感控制里用来"猜"转子位置和速度的算法。滑模观测器抗扰强、实现简单，是工程上最常见的方案，代价是会有抖振。
- **扩展卡尔曼滤波（EKF）**：非线性系统的状态估计方法，无感控制里也用它估位置和速度。**比滑模观测器效果好，但对参数和计算量要求高。**
- **电流采样**：FOC 必须知道三相电流。常见方案是单电阻、双电阻、三电阻采样，**共同点是必须在 PWM 的中点采样**——因为那一刻的开关噪声最小，且电流等于相电流的平均值。
- **标度变换与标定**：标度变换是把 ADC 的原始码值换算成物理量（安培、度）；标定是用已知的基准去修正这个换算关系。**不做标定的采样等于白测。**

### 七、控制与算法

详见 [5.2 控制算法](../05-控制与算法/02-控制算法.md)、[5.3 滤波与姿态解算](../05-控制与算法/03-滤波与姿态解算.md)、[5.5 数据处理与校验](../05-控制与算法/05-数据处理与校验.md)。

- **开环与闭环**：开环不看结果（步进电机开环走步），闭环看反馈（编码器回读再修正）。**闭环不是"更高级"，而是"用传感器换精度"**——没有传感器，闭环无从谈起。
- **比例积分微分控制（PID）**：最常用的反馈控制器。P 管当前误差，I 管累积误差，D 管误差变化率。**工程上 90% 的场合 P 加 I 就够，D 项反而容易放大噪声。**
- **位置式与增量式 PID**：位置式输出的是绝对量，需要累加积分项；增量式输出的是"这次比上次多多少"，天然带抗积分饱和、更适合执行器本身是增量形式的场合（比如步进）。
- **串级 PID 与单环 PID**：串级是"位置环的输出当作速度环的输入，速度环的输出当作电流环的输入"。**多一层环就多一层带宽要求：内环带宽必须明显高于外环，否则整个系统会震荡。**
- **前馈（Feedforward）**：不等误差出现就提前给一个补偿量。**前馈不改稳定性、只减小跟踪误差**——这是它和反馈最重要的区别。
- **积分饱和与抗积分饱和**：误差长期存在时积分项会累加到很大，等误差反向时输出要很久才退回来，表现为大幅超调。抗饱和的做法通常是给积分项加上限，或者输出饱和时停止积分。
- **斜坡函数**：让目标值不要一步跳到位，而是按斜率慢慢加上去。**它就是最简单的运动规划**，用来避免阶跃目标对机械结构的冲击。
- **带宽与相位延迟**：闭环能跟上的频率范围叫带宽；滤波和采样会带来相位延迟。**延迟会让闭环"反应慢半拍"，是震荡的常见根因**——滤波强度不能只按"波形好看"来选。
- **稳态误差、超调、调节时间**：阶跃响应的三个关键指标。稳态误差是最终差多少，超调是最多冲过头多少，调节时间是多久进入允许误差带。**调参时先看这三条，别凭手感。**
- **滑动均值、中值滤波、低通滤波、指数加权移动平均（EWMA）**：四种基础滤波。滑动均值最直观但占内存；中值滤波专门对付偶发野值；低通滤波用频率换平滑；EWMA 是低通的省内存实现，一行代码就能做。
- **互补滤波**：用"高频段信一个传感器、低频段信另一个"的方式融合两路数据。**姿态解算里经典用法是陀螺仪管短期、加速度计管长期**，两者互补。
- **采样定理与混叠**：采样频率必须高于信号最高频率的两倍，否则高频成分会"折叠"成低频假信号。**这是"波形看着对但数值完全不对"的理论解释，且事后无法用软件补救。**
- **运动规划**：解决"从 A 到 B 怎么走"，输出的是时间-位置曲线。它和"轨迹跟踪"（怎么跟上这条曲线）是两件事，不要混。
- **加加速度（Jerk）**：加速度的变化率。**梯形速度曲线的加速度是突变的，Jerk 无限大，会激起机械振动**——S 曲线就是为了让 Jerk 连续。
- **梯形曲线、S 曲线、贝塞尔曲线**：三种常见轨迹形状。梯形是入门，S 曲线更平滑，贝塞尔用于多点连续路径。
- **运动学**：研究位置和速度之间的关系，不涉及力。嵌入式里主要是车轮转速到车体速度的换算、机械臂关节角到末端位姿的换算。
- **差速底盘、麦轮底盘、阿克曼模型**：三种轮式底盘的运动学模型。差速靠左右轮速差转向，麦轮能全向平移，阿克曼是汽车式转向。
- **DH 参数（Denavit-Hartenberg）**：描述机械臂相邻关节之间坐标系关系的四个参数。**它是机械臂正运动学的通用语言，有了它不用为每台机械臂重新推导。**
- **里程计（Odometry）**：靠轮子转了多少推算走了多远。**它一定会漂**——轮子打滑、直径误差、地面不平等都会累积，所以实际系统里要靠别的传感器纠正。
- **循环冗余校验（CRC）与校验和**：两种数据完整性校验。校验和是一段简单的加法取反，计算快但检错能力弱；CRC 检错能力强得多，通信里基本都用 CRC。**校验和不是 CRC 的简化版，是另一套东西。**
- **粘包与帧解析**：串口是字节流，没有天然的"包边界"，所以需要靠帧头、长度、帧尾、超时来切分。**"收不到完整数据"和"收到半包"是同一类问题的两面。**
- **有限状态机（FSM）与层次状态机（HSM）**：状态机把复杂逻辑拆成若干状态加转移条件；层次状态机允许状态嵌套，子状态可以继承父状态的公共转移。**逻辑一复杂，FSM 的状态转移会爆炸，这时候才需要 HSM**——不是所有场合都要上 HSM。
- **表驱动法**：把 if-else 链或 switch 换成查表。**逻辑规则的场合用它，代码更短、更容易改**，但表本身占内存。

### 八、嵌入式 Linux

详见 [8.1 学习路线与环境](../08-嵌入式Linux/01-学习路线与环境.md)、[8.3 驱动开发](../08-嵌入式Linux/03-驱动开发.md)。

- **交叉编译**：在 x86 电脑上编译出能在 ARM 上跑的程序。**这是嵌入式 Linux 和单片机开发在体感上最大的差别**：编译环境和运行环境不是同一台机器。
- **工具链（Toolchain）**：一整套交叉编译工具的集合（编译器、链接器、调试器、库）。名字里带 arm-none-eabi 是裸机，带 arm-linux 的是跑 Linux 的，**选错工具链的报错往往很难看懂**。
- **sysroot**：交叉编译时使用的"目标系统根目录"，里面放着目标平台的库和头文件。**找不到头文件的报错，十有八九是 sysroot 没配对。**
- **根文件系统（rootfs）**：Linux 启动后挂载的第一个文件系统，里面有 /bin、/etc、/lib 这些目录。Buildroot 和 Yocto 是两种常见的构建工具。
- **U-Boot**：嵌入式 Linux 的引导程序，负责初始化硬件、加载内核和设备树、传递启动参数。**它相当于单片机里的 Bootloader，但功能复杂得多。**
- **内核模块（Kernel Module）**：可以动态加载进内核的代码，驱动通常写成模块。**它和应用程序最大的区别是没有 main、不能链接普通 C 库、出错就是内核崩溃。**
- **设备树（Device Tree）**：用文本描述硬件资源的配置文件。**内核不含板级信息，硬件长什么样由设备树告诉它**——这是 ARM Linux 和 x86 Linux 最大的区别。
- **Platform 驱动模型**：Linux 里最简单的驱动模型，把设备和驱动分开注册、由总线匹配。**理解它是理解所有 Linux 驱动的起点。**
- **字符设备与 file_operations**：字符设备按字节流访问，是驱动入门的第一类设备。file_operations 结构体里填的就是 open、read、write 这些函数的实现。
- **设备节点**：/dev 下面的文件，是应用程序访问驱动的入口。**它是个文件，但读写它会进到内核。**
- **procfs 与 sysfs**：两个虚拟文件系统，用来从用户态查看和修改内核状态。**调试驱动时，"往某个文件里 echo 一个值"往往比写程序快得多。**
- **systemd 与 Shell**：systemd 是系统和服务管理器，负责开机启动哪些服务；Shell 是命令行解释器。**这两个是应用层开发每天都在用的东西，先会用再研究。**
- **Makefile 与 CMake**：构建脚本。Makefile 直白但依赖关系要手写，CMake 生成 Makefile、跨平台更好用。**嵌入式项目规模一大，手写 Makefile 就维持不住了。**
- **GDB 与 OpenOCD**：GDB 是调试器，OpenOCD 是它和硬件调试器之间的桥。**命令行调试没有图形界面友好，但它能跑在目标板上、也能自动化，是必须跨过的一道坎。**
- **strace、perf、ftrace**：三个性能与行为分析工具。strace 看系统调用，perf 看 CPU 热点，ftrace 看内核函数调用。**"程序跑得慢"这类问题，靠看代码猜是猜不出来的。**
- **PREEMPT_RT 与中断线程化**：让 Linux 具备硬实时能力的补丁集。核心思路是把中断处理搬到线程里、让高优先级任务随时能抢占内核。**它把 Linux 的实时性从"毫秒级抖动"改善到"几十微秒级"，但仍不等于 RTOS。**
- **CPU 隔离**：把某个 CPU 核从调度器里摘出来，专门跑实时任务，避免被其他任务打扰。**这是实时 Linux 里最有效也最简单的一招。**
- **V4L2、GStreamer、OpenCV、NPU**：摄像头采集、媒体流水线、图像处理库、神经网络加速器。**这是"Linux 负责感知与决策"这条技术路线的工具组合。**

### 九、FPGA 与数字逻辑

详见 [9.1 Verilog 与 RTL 设计](../09-FPGA与数字逻辑/01-Verilog与RTL设计.md)、[9.2 时序分析与跨时钟域](../09-FPGA与数字逻辑/02-时序分析与跨时钟域.md)、[9.3 接口 IP 与软硬协同](../09-FPGA与数字逻辑/03-接口IP与软硬协同.md)。

- **现场可编程门阵列（FPGA，Field-Programmable Gate Array）**：可以用配置数据搭出任意数字电路的芯片。**你写的不是程序，是电路的连接方式**——它没有"执行时间"，只有信号传播延迟。
- **复杂可编程逻辑器件（CPLD）**：比 FPGA 小、逻辑资源少，适合做 glue logic（胶合逻辑，把几个芯片粘起来）。规模小、功耗低、上电即工作。
- **专用集成电路（ASIC）**：为特定用途定制的芯片，流片成本极高但量产单价极低。**FPGA 常被用作 ASIC 流片前的验证平台。**
- **寄存器传输级（RTL，Register Transfer Level）**：一种描述硬件的方式——描述数据在寄存器之间怎么流动、经过什么组合逻辑。它是 HDL 代码的抽象层级。
- **Verilog 与 VHDL**：两种硬件描述语言。**注意它们看起来像代码，描述的是电路**，"把 Verilog 当 C 写"是初学者最大的坑。
- **组合逻辑与时序逻辑**：组合逻辑的输出只取决于当前输入；时序逻辑的输出还取决于时钟沿。**时序逻辑才是能存状态的电路**，大部分设计问题都出在两者混用。
- **综合（Synthesis）**：把 RTL 代码翻译成门级网表的过程。**不是所有 HDL 代码都能综合**，"写得出仿真通过但综合不了"的代码很常见。
- **布局布线（Place and Route）**：把网表映射到 FPGA 的物理资源上并连线。**时序能不能收敛，主要在这一步决定。**
- **静态时序分析（STA）**：不施加激励，直接把所有路径的延迟算一遍，找有没有违反时序要求的路径。
- **建立时间与保持时间**：数据必须在时钟沿之前稳定一段时间（建立时间），并在之后继续保持一段时间（保持时间）。**这是时序分析的全部基础**，两个时间都不满足叫"违例"。
- **时序违例（Timing Violation）**：某条路径没能满足建立或保持时间。**它在硬件上的表现是"偶尔算错一个值"**，不是明显的崩溃，所以比软件 bug 难查得多。
- **时钟约束与约束文件**：告诉工具"我的时钟是多少频率、从哪里来到哪里去"。**不写约束，STA 结果没有意义**——工具会自己瞎猜一个频率，然后告诉你一切正常。
- **跨时钟域（CDC，Clock Domain Crossing）**：信号从一个时钟域传到另一个时钟域。**这是 FPGA 设计里最容易出诡异 bug 的地方**，因为仿真里往往完全正常。
- **亚稳态（Metastability）**：信号在时钟沿附近变化时，触发器可能进入一个既不是 0 也不是 1 的中间状态，且持续时间不确定。**CDC 问题的根源就是它。**
- **两级同步器与打拍**：处理单比特 CDC 的标准做法——用两级触发器串联，让亚稳态有概率衰减。**"打两拍"这个词说的就是它，但要注意它只对单比特信号有效。**
- **异步 FIFO 与握手协议**：处理多比特 CDC 的方案。多比特信号不能简单打两拍，因为各位的延迟不同，可能采到"半新半旧"的组合值。
- **查找表（LUT，Look-Up Table）**：FPGA 里实现组合逻辑的基本单元，本质是一小块可以任意配置真值的存储器。
- **块状存储器（BRAM）与 DSP 块**：FPGA 里的专用硬件资源。BRAM 用来存数据（替代大片寄存器），DSP 块用来做乘加运算。**用不用它们，资源占用能差好几倍。**
- **锁相环（PLL）**：FPGA 内部用来倍频、分频、调整相位的模块。板上的晶振只有一两个频率，其他时钟都靠它生成。
- **IP 核（IP Core）**：别人写好的、可以直接拿来用的功能模块（比如 DDR 控制器、以太网 MAC）。**现代 FPGA 开发的大部分工作是"连 IP"，不是从零写逻辑。**
- **软核与硬核**：软核是用 FPGA 逻辑资源搭出来的 CPU（可以裁剪、但占资源），硬核是芯片里固化的 CPU 电路（速度快、不占逻辑资源）。**同样是 Cortex-M，在 FPGA 里可以是软核也可以是硬核，性能和灵活性完全不同。**
- **AXI、AHB、APB**：三种片上总线标准。AXI 用于高带宽互联，AHB 次之，APB 用于低速外设。**ARM 和 FPGA 通信、FPGA 内部模块互联，都走 AXI。**
- **内嵌逻辑分析仪**：把逻辑分析仪的功能做进 FPGA 内部，抓取内部信号。**它是 FPGA 里最重要的调试工具**——因为内部信号引不出来，用外部示波器根本看不到。
- **软硬协同与异构架构**：ARM 负责逻辑与通信、FPGA 负责高速实时处理的组合方式。**懂一点 FPGA 的嵌入式工程师在这类系统里非常吃香**，因为两边的问题都要能定位。

### 十、硬件与制造

详见 [10.3 电源设计](../10-硬件电路与PCB/03-电源设计.md)、[10.2 原理图与 PCB 设计](../10-硬件电路与PCB/02-原理图与PCB设计.md)、[10.5 信号完整性与 EMC](../10-硬件电路与PCB/05-信号完整性与EMC.md)。

- **原理图（Schematic）**：描述"器件之间怎么连"的图纸，反映的是电气连接关系，不反映位置。**能看懂原理图是软件工程师的最低硬件要求。**
- **印制电路板（PCB，Printed Circuit Board）**：原理图的物理实现。同一张原理图可以画出完全不同的 PCB，性能可能天差地别。
- **EDA 工具与封装库**：立创 EDA、Altium Designer、KiCad 是常见工具；封装库是器件的物理尺寸与焊盘定义。**封装画错，板子回来焊不上，这是新手最常见的翻车方式。**
- **布局与布线（Place and Route）**：先摆器件（布局）再连线（布线）。**布局的重要性远大于布线**——器件摆错了，布线怎么绕都救不回来。
- **铺铜与地平面**：大面积铺上铜并接地，提供低阻抗回流路径、屏蔽干扰、帮助散热。**地平面被割裂是"ADC 采出来全是噪声"的典型根因。**
- **单点接地与回流路径**：单点接地是让模拟地和数字地只在一点相连，避免大电流污染小信号。**关键不是"怎么接地"，而是"电流从哪条路回去"**——回流路径不连续，信号完整性一定出问题。
- **过孔（Via）**：连接不同层之间的孔。它本身有电感，高速信号上的过孔会带来阻抗不连续。
- **线宽与载流**：走线宽度决定能过多大电流。**光看原理图对，线画细了照样烧。**
- **丝印与阻焊**：丝印是板上的白色字符（标号），阻焊是覆盖在铜上的绿油（防止焊锡乱流）。**丝印放错位置会把焊盘盖住，阻焊开窗没做对会焊不上。**
- **设计规则检查（DRC）**：工具按你设定的规则自动查线宽、间距、孔径等。**跑 DRC 是投板前的最后一道防线，别跳过。**
- **层叠（Stack-up）**：多层板的层数安排和介质厚度。**它决定了阻抗能不能控、信号完整性上限在哪。**
- **Gerber 文件**：光绘文件，是 PCB 板厂的通用输入格式。**投板前一定要用 Gerber 查看器过一遍**，因为 EDA 软件里看到的和实际会做出来的可能有差别。
- **物料清单（BOM，Bill of Materials）**：一块板子要买哪些器件、各买多少。它同时是采购清单、贴片机的输入、和成本核算的依据。
- **直插与贴片**：直插元件的引脚穿孔焊接，好焊好拆、适合手工；贴片元件直接贴在焊盘上，体积小、适合机器批量生产，但手工焊难度高。**"通孔"和"直插"说的基本是同一件事。**
- **回流焊与手工焊**：回流焊是过炉子批量焊贴片，手工焊是烙铁一个个焊。**密脚芯片（QFN、BGA）基本只能靠回流焊或者热风枪。**
- **打样与 SMT 贴片**：打样是少量试制，SMT 贴片是让工厂帮你把元件贴上去。**第一次打样一定要选"小批量 + 全检"，别一上来就下单一百块。**
- **首件**：小批量生产时先做一件，检查无误后再批量。**首件确认是省钱的关键动作**，跳过它可能报废一整批。
- **良率（Yield）**：合格品占总产量的比例。**良率突然下降是工艺问题的信号**，不是"运气不好"。
- **失效分析（FA，Failure Analysis）**：对坏掉的板子或芯片做解剖，找出根本原因。**它是设计改进的输入，不是追责的工具。**
- **阻抗匹配**：让源、传输线、负载的阻抗一致，避免信号反射。**高速信号和射频走线必须控阻抗，这要求 PCB 的层叠参数提前定好。**
- **去耦电容**：放在芯片电源引脚旁边的电容，就近提供瞬态电流。**容值不是关键，位置和回路面积才是**——离得远等于没放。
- **串扰与反射**：串扰是相邻走线之间的耦合，反射是阻抗不连续导致的能量折返。**这两者是信号完整性的两大主题。**
- **电磁兼容（EMC）与电磁干扰（EMI）**：EMC 是"既不被干扰、也不干扰别人"的能力，EMI 是实际产生的干扰。**EMC 是经验学科，在真实项目里踩过坑才算真会。**
- **静电放电（ESD）与静电**：人手接触板子时放电打坏芯片。防的手段是接口加保护器件、操作时戴防静电手环。**ESD 造成的损伤有时是"半死"状态**，芯片还能用但会随机出错。
- **低压差线性稳压器（LDO）与开关电源**：LDO 简单、噪声低、但效率低（压差全变成热）；开关电源效率高、能做升降压、但噪声大、设计复杂。**"LDO 还是 DCDC"不是一个对错题，而是"你的负载怕不怕噪声"和"你在不在乎效率"的取舍。**
- **Buck 与 Boost 拓扑**：Buck 降压，Boost 升压，Buck-Boost 升降压。它们是开关电源的基本结构。
- **纹波与噪声**：电源输出上叠加的周期性波动（纹波）和随机波动（噪声）。**测纹波最容易做错的就是探头接地方式**，用错方法测出来的全是假的。
- **环路稳定性**：开关电源的反馈环路要有足够的相位裕度，否则会自激振荡。**它是开关电源设计里最难的部分**，通常靠仿真和实测相位裕度确认。
- **限流与浪涌**：限流是限制最大输出电流；浪涌是上电瞬间的电流冲击。**第一次给新板子上电务必用带限流的可调电源**，这是最省钱的一个习惯。
- **降额与温升**：降额是让器件工作在额定值以下（比如电容只用到耐压的 80%）；温升是器件工作后温度的上升量。**降额不足的板子在常温下正常、在高温环境下批量失效。**
- **车规与 AEC-Q100**：车规是"能用在汽车上"的资质要求，AEC-Q100 是芯片的车规认证标准。**车规器件贵、货期长，但很多场合是硬性门槛。**
- **认证（CE / FCC / CCC）**：产品进入不同市场需要的合规认证。**认证要在设计阶段就考虑，等样机做完了才想起整改，代价大得多。**
- **国产替代**：用国产器件替换进口器件。**不是"引脚兼容就能替"**——要对比电气参数、温漂、寿命、勘误表，还要考虑固件需不需要改。

### 十一、工具与仪器

详见 [11.1 测量仪器](../11-工具仪器与仿真/01-测量仪器.md)、[11.2 调试器与烧录工具](../11-工具仪器与仿真/02-调试器与烧录工具.md)。

- **万用表**：最基础也最该先买的仪器。测通断、测电压、上电前查短路，几十块钱就能解决一半的低级问题。
- **示波器**：看真实电压波形的仪器。三个必须懂的参数：带宽（不够会看到失真的波形）、采样率、触发方式。**探头和接地做错，测出来的全是假的。**
- **逻辑分析仪**：只看高低电平，但通道多、能自动解码协议。**查串口、I2C、SPI 时序用它，比盯着代码看半小时有用得多。**
- **频谱分析仪**：看信号的频率成分，主要用来查干扰和无线信号。**属于"了解即可"的仪器**，一般项目用不上。
- **信号发生器**：产生标准波形，用来给电路加激励。
- **可调直流电源**：能调电压、能限流的电源。**它的核心价值不是供电，而是限流保护**——第一次给新板子上电必须用它。
- **电子负载**：模拟负载去拉电源，用来测电源的带载能力和瞬态响应。
- **调试器（J-Link / ST-Link / DAP-Link）**：把电脑和芯片连起来，用于下载、断点、单步、查看变量。**没有它连程序都下不进去**，选型上看你用什么芯片和预算。
- **JTAG 与串行线调试（SWD）**：两种调试接口。JTAG 引脚多、功能全，SWD 只要两根线、速度也不差，现在是 ARM 上的主流。
- **烧录器与量产烧录**：单件烧录用调试器就行，量产要用专用的离线烧录器或者产线工装。**量产烧录要考虑的是"一次烧几块、坏一块怎么发现"。**
- **串口助手**：最常用的上位机小工具，用来收发串口数据。**调试通信模块的第一步永远是先用它确认模块本身是好的。**
- **内嵌逻辑分析仪（ILA / SignalTap）**：见上文 FPGA 部分的"内嵌逻辑分析仪"条。**它是这一节里唯一一件"仪器在芯片内部"的特例**，调 FPGA 时比任何外部仪器都有用。
- **仿真（Simulation）与硬件在环（HIL，Hardware-in-the-Loop）**：仿真在电脑上跑模型，HIL 是把真实控制器接到模拟的被控对象上。**它们的价值不是替代实物，而是把"上硬件才能发现的问题"提前发现**，但要注意真实系统还有噪声、延时、摩擦、饱和等非理想因素。
- **热风枪与热成像**：热风枪用来拆焊贴片元件；热成像仪用来快速定位哪个器件在发热。**"摸哪个芯片烫"是排查短路最快的办法，但热成像能让你不摸。**

### 十二、工程与流程

详见 [12.1 需求分析与方案选型](../12-工程素养与交付/01-需求分析与方案选型.md)、[12.3 文档·评审·版本发布](../12-工程素养与交付/03-文档·评审·版本发布.md)、[12.4 功能安全与可靠性](../12-工程素养与交付/04-功能安全与可靠性.md)、[12.5 生产交付与 BOM 管理](../12-工程素养与交付/05-生产交付与BOM管理.md)。

- **需求分析与方案选型**：先搞清楚"要做什么、做到什么程度"，再决定"用什么芯片、什么方案"。**方案选型的维度是性能、成本、开发周期、团队能力、供应链、可维护性、认证要求**——只看性能选型，量产时会哭。
- **数据手册（Datasheet）与参考手册与应用笔记**：数据手册讲"这颗芯片是什么、电气参数多少、封装什么样"；参考手册讲"每个寄存器怎么配"；应用笔记讲"厂商推荐的用法"。**这三份文档解决的是不同问题，缺一不可。**
- **勘误表（Errata）**：见"芯片勘误"条。**数据手册是厂商的承诺，勘误表是厂商的补充说明**，遇到诡异现象优先查它。
- **绝对最大额定值（Absolute Maximum Ratings）**：超过就永久损坏的极限值，**不是可以长期工作的范围**。可长期工作的范围看推荐工作条件。
- **代码评审（Code Review）**：让别人看你的代码。**它的价值不在于抓 bug，而在于知识和风格在团队里流动**——一个人踩的坑，评审时全组都学会了。
- **版本号与语义化版本**：用"主版本.次版本.修订号"表达兼容性。主版本升表示不兼容，次版本升表示加了功能且兼容，修订号升表示只修 bug。
- **发布说明（Release Note）**：本次发布改了什么、有什么已知问题。**它是给用户和后续的自己看的**，半年后你会庆幸当初写了。
- **回滚（Rollback）**：出问题退回上一个可用版本。**升级方案里没有回滚路径，等于没有升级方案。**
- **静态分析（Static Analysis）**：不运行程序，直接检查代码。MISRA C 是汽车行业的编码规范，clang-tidy、PC-lint、Coverity 是常见工具。**编译器警告等级开到最高，是成本最低的静态分析。**
- **单元测试与桩函数（Mock）**：单元测试是针对单个函数或模块的测试；桩函数是用假的硬件接口替换真实硬件，让测试能跑在电脑上。**在单片机上做单元测试的关键，就是把硬件访问抽出来。**
- **集成测试与回归测试**：集成测试看模块拼起来对不对；回归测试是每次改动后重跑一遍，确认没弄坏已经好的东西。
- **硬件在环（HIL）**：定义见上文工具与仪器部分的"仿真与硬件在环"条。**汽车行业几乎必用**，因为不可能每次都上真车。
- **持续集成（CI，Continuous Integration）**：每次提交代码自动编译、自动跑测试。**嵌入式项目做 CI 的难点在于硬件依赖**，通常靠桩函数和 HIL 解决。
- **空中下载升级（OTA，Over-the-Air）与差分升级**：OTA 是远程升级固件；差分升级只传新旧版本的差异部分，省流量。**升级方案必须包含固件校验和失败兜底**，否则一次断网就能把设备变砖。
- **功能安全（Functional Safety）与 IEC 61508 / ISO 26262 / ASIL**：功能安全是"把风险降到可接受水平"的一整套方法论。IEC 61508 是通用工业标准，ISO 26262 是汽车标准，ASIL 是汽车里的安全等级（A 到 D，D 最严）。**它和"可靠性"不是一回事**——可靠性关心"会不会坏"，功能安全关心"坏了以后会不会伤人"。
- **冗余与双核锁步**：冗余是同一件事做两遍然后比对；双核锁步是两个内核跑同样的指令、逐周期比对结果，不一致就报警。**这是高安全等级系统里最常见的硬件手段。**
- **失效安全（Fail-Safe）与诊断覆盖率**：失效安全是"出故障时进入安全状态"（比如刹车系统失效就断电抱死）；诊断覆盖率是"能检测出来的故障占全部可能故障的比例"。**没有覆盖率指标，"我加了自检"就是一句空话。**
- **失效模式与影响分析（FMEA）**：系统地列出每个部件可能怎么坏、坏了有什么后果、严重度多高。**它的作用是让风险在设计阶段就被看见，而不是在客户那里被发现。**
- **产测治具与作业指导书**：产测治具是产线上用的测试工装；作业指导书是写给产线工人的操作说明。**"研发能跑通"和"产线能批量做出来"是两件事。**
- **钢网与装配图**：钢网是刷锡膏用的模板，装配图是给产线看"元件装在哪一面"。它们是投板文件包的一部分。
- **供货周期与停产风险**：芯片从下单到到货要多久，以及这颗芯片什么时候会停产。**选型时不看这两项，量产时可能直接停线。**
- **物料编码与替代料**：物料编码是公司内部的器件编号；替代料是参数接近、可以互换的器件。**替代料要在设计阶段就找好，不要等缺货了才临时抱佛脚。**
- **跟线与良率**：跟线是工程师到产线上盯着生产、现场解决问题；良率见前面"良率"条。

## 学习建议

**不建议背这份表。** 术语是查的工具，不是学的对象——背下来的词在你没做过相应项目之前，只是几个不理解的字符串。真正有效的路径是：动手做东西，卡住了，回来查一下，然后再回去做。这样记住的术语是连着场景一起记住的，面试时也讲得出上下文。

**但有几个类别的术语值得在面试前主动过一遍。** 第六类（电机与控制）、第五类（实时操作系统）、第四类（通信协议）是嵌入式面试的高频区，尤其是"电角度与机械角度""优先级反转与优先级继承""半双工与全双工""终端电阻"这几个点，几乎每年都会问到。第四类里的 UART/I2C/SPI/CAN 对比、第五类里的"什么时候不该上 RTOS"，都是能体现判断力的题。

**最值得花时间的是"成对出现"的那些条目。** 这份表里刻意把容易混的术语写在一起，比如 MPU 与 MMU、UART 与 USART、LDO 与开关电源、串级 PID 与单环 PID。面试官问的往往不是"什么是 X"，而是"X 和 Y 有什么区别"——能把这个区别讲清楚，说明你真的用过。

**第一类和第二类的术语容易被忽略，但它们决定你能不能听懂别人说话。** 面试时对方说"这个变量在 .bss 里""你配一下 VTOR"，如果你不知道这是什么，后面的对话就进行不下去了。这两类不需要深挖，能对上号就行。

## 小节总结

这份表的定位是**查阅工具而不是学习材料**。收录的标准是"本教程出现过，而且容易混"，所以它既不完整也不权威——真正的权威永远是数据手册。看这份表的时候要有一个意识：一个术语在数据手册里的定义，可能比这里精确得多，遇到关键参数一定要回去查原文。

组织方式按主题分组而不是按字母排序，是刻意的。术语的意义来自它所在的知识体系——"死区"在电机控制里和在开关电源里不是同一件事，"相位延迟"在滤波里和在时序分析里也不是。按主题分组能让相邻的术语互相定义，这比逐个解释有效得多。

表里最有价值的部分是那些**成对的条目**。嵌入式行业里大量的沟通障碍来自近义词混淆：把 USART 当 UART、把 IAP 当 ISP、把 MPU 当 MMU。这类混淆的代价不是"说错了"，而是排查问题时方向就偏了——你以为在查电源纹波，实际问题在寄存器时钟没开。所以这份表在成对条目上写得比单条更细。

最后一个提醒：**术语的准确使用是专业度的一部分，但不是能力的全部。** 能准确说出"这是死区补偿没做"比背下死区的定义更有价值，因为前者意味着你判断过。所以这份表最理想的用法是——你在项目里碰到问题、查到某个概念、回来对一下名字，然后回到项目里继续干。
