这个文件记录的是**这份教程本身的内容变更**，不是软件更新日志，也不是某个开发板的固件更新说明。它回答的是两个问题：这份教程经历过哪些改动、从旧版本过来的读者需要重看哪几篇。

维护它的理由和 [12.3 文档·评审·版本发布](../12-工程素养与交付/03-文档·评审·版本发布.md) 里讲的一样：**一份会持续修改的文档，必须有地方说明它改了什么**，否则读者拿到两份不同的版本时无从判断差异。教程属于"会被反复查阅的资料"，所以这份记录存在是必要的。

本文件的更新规则很简单：**内容有实质变化就记一条**，包括新增篇目、调整结构、改写大段内容、修正重要错误。错别字修正、链接修补这类不影响阅读的改动不单独记录。

## 本次重构

本次是对教程的一次大规模改版，前后的差异不只是补了几篇，而是**读者定位和整体结构都做了调整**。

### 读者定位调整

改版前，这份教程的定位是**面向校内学生的电控培训资料**，内容围绕校内战队和课程的实际需要组织。

改版后，读者定位调整为**面向泛嵌入式求职者**。这意味着内容要回答的问题变了：不只是"这个技术怎么用"，而是"这个岗位需要什么、面试会问什么、简历上怎么写"。评价每一篇的标准也随之改变——**一篇内容如果不能帮一个想入行或想换方向的人往前走一步，就应该删掉。**

### 章节目录扩展

目录从原来的 5 个目录扩展为 15 个目录，覆盖嵌入式行业的主要方向：

0. 导读
1. 编程与软件基础
2. MCU 与体系结构
3. 嵌入式软件工程
4. 实时操作系统
5. 控制与算法
6. 电机与执行器
7. 通信与物联网
8. 嵌入式 Linux
9. FPGA 与数字逻辑
10. 硬件电路与 PCB
11. 工具、仪器与仿真
12. 工程素养与交付
13. 学习路线与项目实战
14. 附录

调整的依据是**岗位差异**：不同方向的技术栈重合度很高，但需要补的短板差别很大。按方向分章，读者才能只挑自己缺的那部分读，而不是从头翻到尾。

### 新增的重点内容

以下几块是本次改版新增的，也是相对旧版本变化最大的部分：

- **电机与执行器控制**——整章新增，从电机选型、驱动电路、控制算法到位置与电流检测、舵机和步进电机，是控制方向的核心内容。
- **Bootloader 与 OTA 升级**——从设计、分区划分到升级流程和回滚方案，属于实际交付必须掌握的工程能力。
- **调试方法论**——把"怎么定位问题"整理成一套可复用的思路，而不只是罗列工具。
- **代码架构与分层设计**——讲清模块怎么划分、层与层之间怎么约束。
- **工具链与内存布局**——从源码到可执行文件中间发生了什么，以及各类常见链接错误的原因。
- **Flash 存储与参数管理**——掉电保存、磨损均衡、参数版本兼容这些实际项目中反复出现的问题。
- **数据手册阅读方法**——怎么带着问题查阅而不是从头通读。
- **功能安全与可靠性**——面向汽车电子、医疗设备等有认证要求的岗位。
- **生产交付与 BOM 管理**——从样品到量产这一段的流程和物料管理。
- **安全与加密**——通信安全、密钥管理、固件保护。
- **云平台接入**——设备侧如何对接常见物联网平台。
- **协议栈与中间件**——不自造轮子，但要知道轮子在哪一层。
- **实时 Linux 与性能调优**——嵌入式 Linux 方向的进阶内容。
- **视觉与多媒体**——嵌入式视觉方向需要补的部分。
- **接口 IP 与软硬协同**——FPGA 方向中软件和硬件如何配合。
- **项目实战阶梯**——按难度递进的项目清单，给"不知道该做什么"的人一个起点。
- **资源地图**——开发板、工具、资料的选择参考。
- **求职准备**——简历、项目表述、面试准备的实用内容。

### 原有内容全部保留

**原教程的每一节内容都保留在重构后的版本中，只是重新组织到了更合适的位置。**

这一点需要明确说明：本次改版做的是"重新归类 + 补充新增"，不是"替换旧内容"。原有的电控基础、单片机、通信、算法、上位机等部分依然完整，只是从原来按培训流程排列，改成了按技术方向和岗位需要排列。如果你是从旧版本过来的，原有内容大部分都能在新目录里找到对应位置，只是文件名和章节号变了。

### 格式统一

本次改版还统一了各篇的格式：

- **每篇新增统一的篇头四行信息块**：前置知识、掌握标准、对应岗位、练手建议。这四行是给读者的导航，让每个人在决定要不要读这一篇之前就能做出判断。
- **每篇新增篇末导航**：本章目录、总目录、上一篇、下一篇，方便连续阅读和跳转。
- **每章新增章节目录页**：列出本章所有篇目，作为进入一章的入口。
- **统一写作规范**：包括语气、篇幅、术语用法。术语统一的部分见 [14.1 术语表](01-术语表.md)——例如全文统一用"单片机"而不是"微控制器"，统一用"数据手册"而不是直接写 datasheet。

- **2.2 的标题与文件名错了：Cortex-M 是内核，不是架构。** 这一篇一直叫"[2.2 Cortex-M 架构与启动流程](../02-MCU与体系结构/02-Cortex-M内核与启动流程.md)"，但 Cortex-M 是 ARM 的内核产品线（M0、M3、M4、M7、M33……），每条内核实现的是某一代指令集架构——ARMv6-M、ARMv7-M、ARMv7E-M、ARMv8-M。把"内核"说成"架构"是这一行最常见的口误之一，教程自己不该带头，原来的标题会让读者从第一篇起就把这两个概念混在一起。已把标题改为「2.2 Cortex-M 内核与启动流程」，全文其余部分一直是写"Cortex-M 内核"的，正文本身没有跟着错。**标题改了，文件名和全库 11 处链接就必须一起改**（这份教程的约定是文件名等于标题），所以这一条同时动了 [2.1](../02-MCU与体系结构/01-单片机平台选型.md)、[2.3](../02-MCU与体系结构/03-通用外设.md)、[2.4](../02-MCU与体系结构/04-中断系统与低功耗.md) 的篇末导航、[第 2 章目录页](../02-MCU与体系结构/README.md) 两处、[0.2](../00-导读/02-三条路线与技能依赖.md)、[3.6](../03-嵌入式软件工程/06-调试方法论.md)、[14.1](../14-附录/01-术语表.md) 与[仓库首页](../../README.md)。正文补的是《Cortex-M 家族》一节里的"内核 vs 架构"一段——分层关系（ST 的外设 + Cortex-M4 内核 + ARMv7E-M 架构），加上四个能落到工程上的差异：M0/M0+ 用不了 FPU 和 DSP 指令是因为 ARMv6-M 里就没有、编译器的 `-mcpu` / `-march` 必须和芯片对上、TrustZone 从 ARMv8-M（M33）才引入、CMSIS 里部分函数在 M0 上是软件模拟；内核表加了一列"架构"（M0 与 M0+ → ARMv6-M，M3 → ARMv7-M，M4 与 M7 → ARMv7E-M，M33 → ARMv8-M，M55 → ARMv8.1-M）。
- **同一篇里 SysTick 的说法一并订正，并把"内核外设"这个词立起来。** 原文写"SysTick 属于内核而不是外设"，字面没错，但"外设"在嵌入式里默认指片上外设，这句话很容易被读成"SysTick 不是外设"——它是**内核外设**（core peripheral）：挂在私有外设总线 PPB 上，寄存器固定在 0xE000_E010，由 ARM 定义而不是厂商定义，这和厂商挂在片上外设区（0x4000_0000 起）的定时器不是一类。已把那一节的标题、正文和优点清单改成"内核外设"口径，并补上这条分界的用处：**内核外设查 ARM 的架构手册，片上外设查厂商的参考手册**，这正是"这个寄存器该翻哪本书"的答案。异常表里 SysTick 那一行改为"系统节拍定时器，内核外设，不是外设中断"（它是系统异常 15，本来就不该和外设 IRQ 并列），内存映射表里 PPB 那一格补上它实际用到 0xE00F_FFFF 为止。[14.1 术语表](../14-附录/01-术语表.md) 同步改了四处：`芯片内核（Core）` 原来写成"CPU 的架构版本"，正是上面那个混淆的源头，已改成内核不等于架构并说明 Cortex-M4 实现的是 ARMv7E-M；新增 `指令集架构（ISA）与 ARMv6-M / ARMv7-M / ARMv7E-M / ARMv8-M` 与 `内核外设与片上外设` 两条（在此之前全库从未出现过架构版本号，也没有"内核外设"这个说法）；SysTick 条目补上 PPB 地址、不需要开 RCC 时钟、异常号固定 15；NVIC 条目里"配置方式和别家架构不一样"改为"别家芯片"。
- **[0.3 怎么用这份教程](../00-导读/03-怎么用这份教程.md) 的典型读法补了第四种人。** 原来只列了三种——零基础的学生、有编程基础想转行、已经在职想补短板——漏掉了人数最多的一类：已经在学嵌入式（板子有了、例程也会改），却不知道该学下一项的人。他们不是零基础，也不属于转行或补短板，三种读法里没有一种对得上。新增的《如果你正在学嵌入式，但不知道下一步该学什么》给的是三步定位：先用 [13.1 方向路线图](../13-学习路线与项目实战/01-方向路线图.md) 的四阶段表看清自己在哪个阶段，再沿 [0.2 三条路线与技能依赖](../00-导读/02-三条路线与技能依赖.md) 的技能依赖图从下往上找出第一个说不清的节点，最后用一个比现在高一档的项目（[13.2 项目实战阶梯](../13-学习路线与项目实战/02-项目实战阶梯.md)）把下一步钉住；另加两条容易被忽略的提醒——能通过篇头"掌握标准"的部分直接跳过，以及不要在依赖图上跳级（回指本篇误区三）。小节标题由《三种典型读法》改为《四种典型读法》。

## 版本号约定

这份文件本身不使用数字版本号，只按时间顺序追加条目。原因是教程的变化不适合用「主版本.次版本.修订号」衡量：改一篇的篇幅和新增一章的篇幅无法比较，硬编版本号反而增加维护负担。

实际的约定是：

- **有实质变化就记一条**，追在最新一条之后。
- **一条记录里说明改了什么、为什么改**，而不只是写"更新若干篇"。
- **不记录具体日期**，因为教程的修改是持续零散进行的，精确日期既不必要也不可靠。
- **如果改动纠正了之前版本的重要错误，要在条目里明确说明**，方便读到过旧版本的读者知道要重新看哪里。
