# 3. 嵌入式软件工程

**这一章的内容不会让你的项目"多一个功能"，但会决定你的项目能不能交付、能不能维护、以及你能不能定位故障。**

很多人在学生阶段觉得这些是"虚的"，工作以后才发现它们是硬门槛。一个能写出功能但代码一团乱、出了问题只会瞎改的人，和一个代码结构清晰、能拿着工具定位故障的人，职业发展相差很远。

| 篇目 | 内容 | 难度 |
|---|---|---|
| [3.1 代码架构与分层设计](01-代码架构与分层设计.md) | HAL/BSP/APP 三层划分、驱动抽象与接口设计、状态机组织复杂逻辑、表驱动法、模块解耦 | ★★★ |
| [3.2 构建系统与工具链](02-构建系统与工具链.md) | 编译链接流程、GCC/arm-none-eabi、Make/CMake/Ninja、链接脚本与 map 文件、Keil/IAR 与命令行的取舍 | ★★★ |
| [3.3 Git 与代码托管](03-Git与代码托管.md) | Git 核心命令与分支模型、.gitignore、GitHub/Gitee、README 怎么写 | ★★ |
| [3.4 代码规范与静态分析](04-代码规范与静态分析.md) | 命名与风格、头文件守卫、MISRA C 简介、clang-tidy/PC-lint/Coverity、编译器警告等级 | ★★ |

## 适合谁

- **所有人**：3.1、3.2、3.6 建议所有人都读。
- **想找工作的学生**：3.6 是面试高频考点——"你的程序跑飞了怎么查"这道题筛掉了大部分人。
- **在职工程师**：3.4、3.5、3.7 是往规范化工程走必须补的。

## 通读顺序建议

```
3.2 构建系统与工具链  →  3.1 代码架构与分层设计  →  3.6 调试方法论
                                                        ↓
                                              3.7 Bootloader 与 OTA
                                                        ↓
                                        3.3 Git  →  3.4 代码规范  →  3.5 测试
```

**3.6 调试方法论是全章、甚至可能是全教程最实用的一篇。** 它讲的是"遇到问题怎么找原因"，这个能力比任何一个具体技术点都更值钱。
