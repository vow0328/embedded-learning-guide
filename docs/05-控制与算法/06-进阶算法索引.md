# 5.6 进阶算法索引

> **前置知识**：[5.1 常见算法总览](01-常见算法总览.md)
>
> **掌握标准**：知道进阶算法有哪些、各自解决什么问题、想深入时该往哪个方向找，不会因为"看不懂"而焦虑
>
> **对应岗位**：算法工程师 · 电机控制工程师 · 机器人工程师 · 无人机工程师 · 信号处理工程师
>
> **练手建议**：从本篇七类里挑一类你方向相关的，只挑其中最简单的一个算法（比如观测与估计里的龙伯格观测器），花一周把它实现一遍

## 这一篇是索引，不是教程

以下内容不要求必须掌握，但了解它们的存在和适用场景，会让你在面对复杂问题时多一些解决思路。同时，这些内容也是从普通电控开发逐步走向算法岗、机器人岗、控制岗的重要进阶方向。

所以读这一篇的心态要摆正：**它的目标是让你建立"地图感"——知道有这些东西、各自解决什么问题——而不是现在就把它们学会。** 看到不认识的算法名，只需要记住它属于哪一类、能干什么，具体实现等到项目真的需要时再回来。

## 进阶算法是常见算法的自然延伸

这七类算法不是凭空冒出来的另一套体系，它们大多是在常见算法碰到天花板时延伸出来的：

- 一阶低通滤不掉模型内部的噪声 → 卡尔曼、EKF（观测与估计）
- PID 调不出多变量、带约束的最优性能 → LQR、MPC（现代控制与优化）
- 时域看不出问题、想知道信号里有什么频率 → FFT、小波（信号处理）
- 控制器效果依赖模型，但模型参数没人给 → 最小二乘、系统辨识（参数辨识）
- 想让设备自己报告"我要坏了" → 残差法、频谱特征（故障诊断）
- 传输不可靠、需要在数据部分损坏后恢复 → Reed-Solomon、LDPC（编码与通信）
- 公式算得动但单片机算不快 → 查表、插值、CORDIC（数值计算）

沿着这条线索读，你会发现进阶算法并不神秘——**每一个都对应一个前面解决不了的痛点**。当你真的在某一天被这个痛点卡住时，再回来查对应的那一类，学习动力和效果都会比现在硬看强得多。

## 1. 观测与估计

| 算法 | 说明 | 典型应用 |
|------|------|----------|
| 状态观测器 | 根据可测输出估计不可直接测量的内部状态 | 电机控制中估计转子位置和速度 |
| 龙伯格观测器 | 经典线性状态观测器，通过误差反馈修正状态估计 | 线性系统状态估计 |
| 扩展卡尔曼滤波（EKF） | 对非线性系统进行一阶线性化后的状态估计 | IMU姿态解算、多传感器融合 |
| 无迹卡尔曼滤波（UKF） | 用采样点传播状态分布，避免显式线性化 | 高精度姿态估计、目标跟踪 |
| 粒子滤波 | 用大量随机粒子逼近状态概率分布 | 机器人定位、SLAM、目标跟踪 |
| 滑模观测器（SMO） | 鲁棒性强，对模型误差不敏感 | 无感FOC、电机状态估计 |

这一类算法解决的核心问题是"有些关键状态测不到，能不能根据现有信息估算出来"。比如无感电机控制中没有编码器，系统需要根据电流电压推算转子位置；姿态解算中无法直接测到姿态角，只能通过多传感器数据融合来估计。龙伯格观测器是理解状态估计的基础入门，EKF是工程中最常用的非线性估计方法，UKF和粒子滤波则适合更复杂的高精度场景。如果以后你想往电机控制、姿态估计、传感器融合方向深入，这一类算法会非常关键。

## 2. 现代控制与优化

| 算法 | 说明 | 典型应用 |
|------|------|----------|
| LQR | 线性二次最优控制，在性能和能耗之间寻找平衡 | 平衡车、无人机姿态控制 |
| LQG | LQR与卡尔曼滤波结合，处理带噪声的最优控制 | 有噪声系统的最优控制 |
| MPC（模型预测控制） | 利用系统模型进行滚动优化控制 | 路径跟踪、高性能控制 |
| 自适应控制 | 控制器参数随系统特性变化而自动调整 | 负载变化大的系统 |
| 鲁棒控制（H∞） | 在存在模型不确定性时保证稳定性和性能 | 高可靠控制系统 |
| 滑模控制（SMC） | 通过设计滑模面增强抗干扰能力 | 机器人控制、电机调速 |
| 模糊控制 | 不依赖精确模型，用模糊规则实现控制 | 难以建模的系统 |
| 最小二乘法 | 通过最小化误差平方和估计参数 | 标定、辨识、拟合 |
| 梯度下降 | 沿误差下降方向迭代优化参数 | 参数调优、机器学习基础 |
| 遗传算法 / 粒子群优化（PSO） | 不依赖梯度的全局优化方法 | PID整定、多参数优化 |

这一类算法比PID更强调系统模型、性能指标和全局最优。LQR适合线性系统的最优控制，LQG在LQR基础上引入卡尔曼滤波处理噪声，MPC则更适合多变量、有约束的复杂控制场景。滑模控制和鲁棒控制更强调在模型不准、存在干扰的情况下仍然保持系统稳定。模糊控制则适合那些难以建立精确数学模型但经验规则比较清晰的对象。最小二乘法、梯度下降、遗传算法、粒子群优化这些优化工具，在参数辨识、自动调参和系统优化里非常常见。整体来说，这一类算法是从"能控制"走向"控制得好"的关键跃迁点。

## 3. 信号处理

| 算法 | 说明 | 典型应用 |
|------|------|----------|
| FFT（快速傅里叶变换） | 将时域信号转换到频域分析 | 振动分析、故障检测、频谱显示 |
| STFT（短时傅里叶变换） | 分段进行频谱分析，兼顾时域和频域 | 语音处理、非平稳信号分析 |
| 小波变换 | 多分辨率时频分析方法 | 故障诊断、瞬态检测 |
| FIR滤波器 | 有限脉冲响应滤波器，相位线性、稳定性好 | 音频处理、精密滤波 |
| IIR滤波器 | 无限脉冲响应滤波器，效率高、阶数低 | 实时滤波、嵌入式信号处理 |
| 自相关 / 互相关 | 分析信号周期性和相似性 | 周期检测、时延估计、匹配 |
| PLL（锁相环） | 跟踪输入信号频率与相位 | 电网同步、解调、频率跟踪 |
| 陷波器 | 针对特定频率进行抑制 | 工频干扰消除、机械共振抑制 |

这一类算法主要解决"信号里到底有什么、怎么把有用成分提取出来"的问题。FFT是最基础的频域分析工具，能让你看到信号的频率组成；STFT和小波变换则适合频率成分会随时间变化的场景。FIR和IIR是两类主要的数字滤波器，FIR相位线性、稳定性好，IIR计算效率更高。陷波器在消除工频干扰或机械共振时非常实用，PLL在电网同步和通信解调中是核心组件。如果你以后接触电机故障诊断、振动分析、音频处理或者电能质量方向，这一类算法会是重点。

## 4. 参数辨识与系统辨识

| 算法 | 说明 | 典型应用 |
|------|------|----------|
| 最小二乘法 | 利用误差最小化进行参数拟合 | 传感器标定、参数估计 |
| 递推最小二乘（RLS） | 在线更新参数估计，适合实时场景 | 在线辨识、实时建模 |
| 系统辨识 | 根据输入输出数据建立系统模型 | 控制对象建模 |
| ARX / ARMAX模型 | 常见离散系统辨识模型 | 工业过程辨识 |
| 曲线拟合 | 根据样本数据构建函数关系 | 传感器标定、补偿函数生成 |
| 在线参数估计 | 系统运行过程中动态估计参数 | 时变系统、自适应控制 |

这一类算法解决的是"系统模型不知道、参数不准，怎么估出来"的问题。很多控制算法要想效果好，前提是你得知道系统大概长什么样，但现实里很多对象都没有现成的精确模型，这时就需要靠辨识算法去估计。比如电流传感器标定、电机参数估算、控制对象传递函数未知，都可能会用到这类方法。参数辨识往往决定了后续控制器能不能真正调好，是一个不显眼但很重要的方向。

## 5. 故障诊断与健康监测

| 算法 | 说明 | 典型应用 |
|------|------|----------|
| 残差法 | 利用模型输出与实际输出的偏差判断异常 | 控制系统故障检测 |
| 阈值检测 | 通过设定阈值识别异常状态 | 基础故障报警 |
| 卡方检测 | 基于统计量检测异常 | 传感器异常判断 |
| 频谱特征分析 | 利用频域特征识别故障 | 轴承故障、电机振动分析 |
| 异常检测 | 识别偏离正常模式的数据 | 设备监测、预测性维护 |
| 健康状态评估 | 综合多项指标判断设备健康程度 | 工业设备、电池状态评估 |

这一类算法解决的是"设备有没有坏、现在的状态是不是正常"的问题。最简单的是阈值检测，比如温度超限就报警；更进一步的是基于模型残差或频谱特征来识别具体的故障类型，比如轴承磨损、电机匝间短路等。在普通电控学习路线里这一块容易被忽略，但在工业控制、电机维护、电池管理系统等方向上非常重要。随着设备智能化程度的提高，故障预测和健康监测会越来越成为主流需求。

## 6. 编码与通信

| 算法 | 说明 | 典型应用 |
|------|------|----------|
| 哈夫曼编码 | 基于频率构建无损压缩编码 | 数据存储与传输优化 |
| Reed-Solomon | 前向纠错编码，支持部分数据损坏后恢复 | 通信抗干扰、二维码、存储纠错 |
| 卷积码 / Turbo码 / LDPC码 | 不同性能等级的信道编码方法 | 无线通信、深空通信、抗误码 |
| 协议状态机 | 管理通信协议的收发流程 | 串口协议、网络协议开发 |
| Base64 / Hex编码 | 将二进制数据转成文本格式传输 | 数据传输、调试输出 |

这一类算法主要解决"数据怎么更可靠、更高效地传输和解析"的问题。CRC、数据帧解析这些常用内容已经放在前面的常见算法里了，这里的内容更偏进阶和深入。Reed-Solomon在二维码、光盘、卫星通信中应用极广，理解它有助于明白为什么数据在部分损坏的情况下仍然能恢复。协议状态机在复杂通信协议开发中几乎是标配。Base64和Hex虽然简单，但在实际调试和协议封装中使用频率很高。如果你以后往通信、网络设备、嵌入式协议栈方向走，这部分内容值得深入。

## 7. 数值计算与快速求解

| 算法 | 说明 | 典型应用 |
|------|------|----------|
| 牛顿迭代法 | 迭代求解非线性方程 | 逆运动学、参数求解 |
| 二分法 | 简单稳定的数值求根方法 | 函数零点求解 |
| 线性插值 / 多项式插值 | 用离散点逼近连续函数 | 查表补偿、传感器校准 |
| 查表法 | 预先存储计算结果以提高运行速度 | 三角函数近似、控制补偿 |
| CORDIC | 高效求解三角函数和反三角函数 | 资源受限平台数学计算 |
| 矩阵分解 | 用于线性方程组求解和优化问题 | 控制计算、滤波算法 |

这一类算法平时不一定被单独称作"电控算法"，但在嵌入式开发里非常实用。很多公式理论上能算，但单片机算得太慢或者浮点资源有限，这时候就需要查表法、插值法、CORDIC这类方法来加速。比如FOC控制中需要大量三角函数运算，用CORDIC或查表替代标准math库可以显著提升执行速度。机械臂逆运动学求解、卡尔曼滤波中的矩阵运算，本质上也都离不开数值计算方法。这部分内容往往不显眼，但真正做复杂系统时会频繁遇到，是工程落地中不可忽视的一环。

## 数值计算为什么在嵌入式里特别重要

第七类值得单独展开说，因为它是"理论能算"和"实际算得动"之间的那道门槛。

PC 上的程序很少需要考虑"这个三角函数要花多少时间"，因为 CPU 有几 GHz 主频和强大的浮点单元。单片机上完全不同：一颗 72 MHz 的 Cortex-M3 没有硬件浮点，调用一次标准库的 sin 函数可能要几百个时钟周期；而电流环的控制周期可能只有 50 微秒，也就是 3600 个时钟周期。**在一个循环里调用十次三角函数，控制周期就没了。** 这不是优化技巧，而是能不能跑起来的问题。

三种典型的应对手段：

- **查表法**：把函数在一个周期内的值预先算好存进数组，运行时按索引取值。代价是精度受表长限制，好处是查询几乎是常数时间（一次数组访问）。三角函数、S 形曲线、非线性补偿曲线都适合查表。
- **插值**：表长总是有限的，为了在表项之间得到更细的值，就在相邻两项之间做线性（甚至二次）插值。**查表加线性插值是嵌入式里最通用的加速组合**，几乎每个高性能电机控制项目里都有它的身影。
- **CORDIC**：一种用移位和加法迭代逼近三角函数、反三角函数、开方等运算的算法。它最大的价值是只需要加法和移位——这两种操作在任何单片机上都是单周期或接近单周期的，完全不需要乘法器和浮点单元。在一些没有硬件乘法的低端芯片上，CORDIC 几乎是唯一的选择。

再往上走，矩阵分解、迭代求根（牛顿法、二分法）这类方法在卡尔曼滤波、机械臂逆解、参数辨识里都会遇到。它们通常不需要你自己从零实现（有现成的库），但**需要你知道"这个运算在这个芯片上大概要花多少时间"**——这是选型和架构阶段就要判断的事。等到做出来发现周期不够用再回头改算法，代价会大得多。

## 按方向推荐的阅读优先级

进阶算法索引不要求全部掌握，更不建议一上来就全部投入学习。更合理的方式是先把常见算法部分打牢，遇到基础算法解决不了的问题时，再根据方向有针对性地深入。

- 做电机控制方向，重点看观测与估计、现代控制、信号处理相关内容。
- 做机器人和导航方向，重点看路径规划、定位与建图、参数辨识相关内容。
- 做工业控制和设备监测方向，重点看故障诊断、系统辨识、鲁棒控制相关内容。
- 做通信和协议方向，重点看编码与通信、协议状态机相关内容。
- 对前沿方向感兴趣，可以了解智能控制和TinyML相关内容。

## 入门顺序建议：每一类里先拿哪个练手

如果你决定动手试一试，从每一类里挑一个门槛最低的，比挑最"有用"的更划算——先建立手感，再谈深入。

| 类别 | 建议的第一个 | 理由 |
|------|--------------|------|
| 观测与估计 | 龙伯格观测器 | 结构最简单，只用误差反馈修正状态，理解了它再看 EKF 就是加了统计权重 |
| 现代控制与优化 | 最小二乘法 | 数学门槛最低，用途最广，标定和拟合立刻能用上 |
| 信号处理 | FFT | 有现成库，输入一段真实数据就能看到频谱，正反馈最强 |
| 参数辨识 | 曲线拟合 | 本质是最小二乘的应用，可以拿自己的传感器数据直接练 |
| 故障诊断 | 阈值检测 | 半小时能写完，几乎所有项目都在用，先把它做扎实 |
| 编码与通信 | 协议状态机 | 和 5.5 的收包解析是同一件事，练手的同时改进你的项目 |
| 数值计算 | 查表加线性插值 | 最容易见效，能直接感受到"速度提升一个数量级" |

这张表的用法是：**选一个和你方向相关的，只做那一个，做完再回来挑第二个。** 一次投入一类，不要并行。

## 学习建议

算法这条路没有终点，重要的是先知道有哪些工具可以用，遇到问题时知道往哪个方向去找答案。

- **本篇当字典用，不要当教材读。** 通读一遍建立地图感就够了，不要试图记住表格里的每一条。
- **不要因为看不懂而焦虑。** 这些算法各自都有一门课的量，看不懂是正常的。你对它们的要求只是"知道有这么回事、需要时能顺着名字去查"。
- **从"最小可用的那个"入手。** 上面那张入门顺序表就是为此准备的。把一个简单算法从头到尾实现并验证一遍，比泛读十个算法的介绍有价值得多。
- **注意，算法覆盖面非常广，目前也没有一套真正适合所有人"从头看到尾就能学会"的通用课程。** 很多算法本身就偏理论，最终还是要靠仿真、代码实现和项目应用来真正理解。所以在学习算法时，不必追求面面俱到，更建议采用"用到什么学什么"的方式：项目需要哪类算法，就去重点补哪一类。这样效率更高，也更容易把理论和实际结合起来。
- **先做完 5.2 到 5.5。** 在 PID 和滤波还没用熟之前投入进阶算法，投入产出比很低，而且容易产生"学了很多但项目还是做不出来"的挫败感。

## 小节总结

这一篇的价值在于消除未知带来的焦虑。很多人在面试或看资料时被"卡尔曼""MPC""小波变换"这类名词劝退，觉得自己差了很远；实际上这些算法各自解决的是很具体的问题，用到时再学完全来得及。知道它们各自管什么，就已经跨过了大部分障碍。

七类进阶算法其实对应七种不同的工程需求：测不到的状态、控不好的性能、看不出的频率成分、摸不准的模型参数、判断不了的故障、传不稳的数据、算不动的公式。遇到问题时能把现象归到其中之一，就知道该往哪个方向查——这和 5.1 讲的"算法意识"是同一件事的延伸。

按方向推荐的阅读优先级，本质上是提醒你"不要全都学"。电机、机器人、工业监测、通信几个方向的侧重点差别很大，照着别人的学习路线走只会浪费时间。选自己方向相关的那几类，其余的知道存在就够了。

最后要清楚这一篇和前面几篇的关系：5.2 到 5.5 是"必须会"，这一篇是"可以以后会"。把有限的时间先投在必须会的东西上，是更稳妥的顺序。
