# 2.1 单片机平台选型

> **前置知识**：[1.1 C 语言（嵌入式视角）](../01-编程与软件基础/01-C语言（嵌入式视角）.md)
>
> **掌握标准**：能说清主流单片机平台各自的定位与取舍，知道国产 MCU 替代的边界在哪里，并能为自己要做的项目选出合适的平台
>
> **对应岗位**：全部嵌入式软件岗位（选型判断是嵌入式工程师的通用能力，不是某一类岗位专属）
>
> **练手建议**：拿你手上或打算买的一块板子，对照本篇的选型维度（内核、主频、Flash/RAM、外设、封装、生态、供货）逐项查一遍数据手册，看看它适合做什么、不适合做什么

## 选平台是第一个绕不开的决定

单片机种类繁多，常见的有 STC89C51、STM32、ESP32、ESP8266、TI MSP430 系列等。Arduino 严格来说不是一款芯片，而是一个开发平台/框架，但因其使用极为广泛，这里一并介绍。

**为什么把它放在整章的第一篇？** 因为它是你每次做项目的第一个决定，而这个决定错了，后面所有的工作都会变得别扭：想做电机控制却选了一颗没有高级定时器的芯片，想做物联网却选了一颗没有无线外设的芯片，想量产却发现这颗料交期三十六周。

**芯片选型的成本不在芯片本身，而在它带来的所有约束。** 这一篇的目的是让你在看数据手册之前，先建立起一套判断框架。

## STM32

STM32 是意法半导体（ST）推出的 32 位单片机系列，基于 ARM Cortex-M 内核，是目前国内嵌入式领域使用最广泛的平台之一，也是大多数方向最推荐优先学习的单片机。

不同系列之间 HAL 库的 API 接口几乎一致，掌握一个系列之后换芯片的迁移成本很低，这也是 STM32 生态的一大优势。

开发方式主要有两种：

- **标准库**：直接操作寄存器的封装库，代码执行效率高，但配置繁琐，而且 **ST 官方早已停止更新**——它只覆盖 F0/F1/F2/F3/F4/L1 这些老系列，之后的 G0、G4、H7、L4、U5 从一开始就只有 HAL，没有标准库。**不必专门学它**：新项目不会用，新芯片也配不到；将来接手存量老项目时要能看懂，但那是"对着手册改"的量级，用到时再学完全来得及。
- **HAL 库**：ST 官方主推的现代开发方式，配合 STM32CubeMX 图形化工具使用。CubeMX 可以通过点选的方式配置引脚复用、外设参数、时钟树等，一键生成初始化代码框架，开发效率大幅提升。推荐新手直接从 HAL 库开始学习。

学习路径建议：先把 GPIO、EXTI、TIM、PWM、ADC、UART 这几个最基础的外设掌握，具备这些能力之后就可以开始做实际项目了。后续根据项目需求再逐步学习 SPI、I2C、CAN、DMA 等通信和数据传输外设。

**STM32 的真正价值不只在芯片本身，而在于它周边的一切**：中文教程最多、开源项目最多、遇到问题时能搜到的答案最多。对初学者来说，**"搜得到答案"这一项的重要性往往被严重低估**——它决定了你卡住的时候是花十分钟还是花三天。

也正因如此，STM32 有一套公认的入门视频：江协科技的 [STM32 入门教程（2023 版）](https://www.bilibili.com/video/BV1th411z7sn)——33 小时、逐个外设手把手讲，把每个外设是干什么的、寄存器里每一位是什么意思讲得很清楚，是很多人真正意义上的第一门嵌入式课。**它值得完整看一遍，但正确的用法是：看它的讲解，代码自己用 HAL 实现一遍。** 它的代码是标准库写的，而标准库不必学；可它的**原理部分不会白学**——时钟怎么开、中断向量怎么回事、外设初始化的顺序，两种库完全共通，区别只在 API 长相（标准库是 `GPIO_Init()` 配 `RCC_APB2PeriphClockCmd()`，HAL 是 `HAL_GPIO_Init()` 配 `__HAL_RCC_GPIOA_CLK_ENABLE()`）。

**这个"看讲解、自己写"的组合，其实是比照抄更有效的练法**：你已经知道这一步要做出什么效果，任务就变成了"在 HAL 里找到对应的接口"，而这正是日后读手册、换芯片时每天都要做的动作。反过来，照着视频把标准库代码敲一遍，你只是把三十小时花在了一套新项目不会用的 API 上。

如果连"用 HAL 该怎么写"也想先看别人示范，[14.3 致谢](../14-附录/03-致谢.md) 里提到的 **《中科大 RM 电控合集》** 正好补上这一环：它从 STM32CubeMX 起步，基础篇讲的外设（GPIO、EXTI、TIM、UART、PWM、ADC）就是上面那条学习路径要掌握的那几个，全程用 HAL；再往后是电机控制篇（CAN、多环 PID、前馈）和开发工具篇（Git、CMake、CLion、调试），正好接上本教程的 [第 3 章](../03-嵌入式软件工程/README.md)、[第 5 章](../05-控制与算法/README.md) 和 [第 6 章](../06-电机与执行器/README.md)。**如果你的方向是电机或机器人，这套比任何入门课都贴目标。**（那一页同时有合集入口和配套代码仓库。）

无论跟哪一套，跑完之后都要回到数据手册和参考手册，把"为什么这么设计"这一层补上（方法见 [12.2 数据手册阅读方法](../12-工程素养与交付/02-数据手册阅读方法.md)）。

## Arduino

Arduino 不是某一款具体芯片，而是一个开源硬件开发平台，底层芯片可以是 AVR（如 ATmega328P）、ARM（如 SAMD21）甚至 ESP32。Arduino 的核心优势是极低的上手门槛：底层寄存器操作全部封装成简单易懂的函数调用，几乎所有传感器和功能模块都有现成的库，安装之后直接调用接口即可，非常适合快速验证想法和做原型开发。

但这种高度封装也是它的局限所在。Arduino 隐藏了大量底层细节，使用者很难真正理解硬件在做什么，遇到性能瓶颈或需要精确时序控制时，Arduino 的封装反而会成为障碍。因此，Arduino 更适合作为入门体验或快速原型的工具，而不适合作为深入学习嵌入式开发的主要平台。

**一个务实的用法**：做原型验证、参加比赛快速搭出 Demo、给非电子背景的人做演示——Arduino 是最快的路径。但如果你的目标是求职，**简历上只有 Arduino 项目是不够的**，因为它体现不出对底层机制的理解。建议尽早过渡到能直接接触寄存器和工具链的平台。

## ESP32

ESP32 支持多种开发方式，新手推荐直接使用 Arduino 框架入门，在 Arduino IDE 或 VSCode + PlatformIO 中安装 ESP32 支持包，能快速跑起来第一个程序。熟悉基本流程之后，再考虑切换到乐鑫官方的 ESP-IDF 框架，功能更完整，对 FreeRTOS、WiFi 协议栈、蓝牙协议栈的支持也更好。

ESP32 的 GPIO、UART、SPI、I2C 等外设用法和 STM32 思路基本一致，有 STM32 基础的话上手很快。重点学习 WiFi 连接（Station 模式连接路由器、AP 模式创建热点）和基础的 TCP/UDP 通信，这是 ESP32 区别于普通单片机的核心能力。

掌握基础通信之后，可以尝试接入 MQTT 协议，与云平台对接，实现设备远程控制和数据上报。这一步做完，基本就具备了独立完成一个完整物联网项目的能力。云平台侧的工程问题（配网、重连、离线缓存、远程配置）见 [7.4 云平台接入](../07-通信与物联网/04-云平台接入.md)。

**ESP32 的定位很清晰**：它是"带无线能力的单片机"，成本低、开发快，是物联网方向最省事的入门选择。但它的实时性和外设精度不如 STM32 的高端系列，做电机控制、精密测量这类任务时要谨慎评估。

## TI MSP430 系列

MSP430 是 TI 的老牌系列，最突出的特点是**超低功耗**——在很多场景下它的待机电流能做到同类产品中的领先水平。它也曾是某些竞赛和教学场景的指定平台，因此资料并不少。

不过日常学习和项目开发仍建议以 STM32 为主，原因有几点：MSP430 是 16 位架构，性能相对有限；TI 的开发生态和中文社区资料不如 ST 丰富；MSP430 的调试体验也相对一般，锁芯片（调试接口被意外锁死）的情况时有发生且处理麻烦。

**MSP430 更适合作为低功耗场景下的专项选择，而非主力学习平台。** 如果你的产品核心指标是"一颗纽扣电池用三年"，那它值得认真评估；如果只是常规的功能开发，STM32 一类会顺手得多。

## 国产 MCU：绕不开的一课

**这一节在国内做嵌入式，是必须知道的。** 近几年国产 MCU 在中低端市场已经大量替代了进口型号，很多产品的 BOM 里都有它们。你未来面试和工作时几乎一定会遇到。

### 为什么会出现国产替代

| 动因 | 说明 |
|---|---|
| **供货与交期** | 前几年的缺货潮让很多公司意识到"单一供应商"的风险，开始主动做备份方案 |
| **成本** | 国产型号在同规格下通常有明显价格优势，走量的产品对成本极其敏感 |
| **自主可控** | 部分行业（电力、能源、工业控制、汽车）有明确的国产化要求 |
| **生态成熟** | 早期的国产芯片"能用但难用"，现在工具链、库、文档已经补齐很多 |

### 主要厂商与产品线

下面这些是你在选型和面试中会反复遇到的，**只列定位，不评价优劣**——具体型号的能力以厂商最新数据手册为准：

| 厂商 | 代表系列 | 常见定位 |
|---|---|---|
| **兆易创新（GigaDevice）** | GD32 | 与 STM32 引脚和寄存器高度相近，是替代方案里最常见的一类 |
| **沁恒（WCH）** | CH32 | 性价比突出，部分型号带 USB 和无线能力 |
| **极海半导体（Geehy）** | APM32 | 工业与汽车方向布局较多 |
| **国民技术（Nations）** | N32 | 安全与通用 MCU 并行 |
| **华大半导体（HDSC）** | HC32 | 低功耗与通用系列 |
| **灵动微（MindMotion）** | MM32 | 通用与电机控制方向 |
| **航顺芯片** | HK32 | 通用中低端市场 |
| **中微半导体** | CMS32 | 消费类与小家电 |

另外还有大量做专用方向（电机驱动、触控、无线、蓝牙 SoC）的厂商。**这个名单会持续变化**，具体到某个项目该选谁，要看当时的供货、价格和支持力度。

### "兼容"到底兼容到什么程度

这是国产替代里最需要搞清楚的一件事。**"兼容"不是一个二元概念，它有三个层次：**

| 层次 | 含义 | 迁移工作量 |
|---|---|---|
| **引脚兼容** | PCB 不用改，可以直接换料 | 最小 —— 但只是硬件层面 |
| **寄存器兼容** | 寄存器地址和位定义基本一致，寄存器级代码能直接跑 | 中等 —— 外设行为可能仍有差异 |
| **库兼容** | 厂商提供了与 HAL/标准库接口高度一致的库，甚至提供移植工具 | 最小 —— 但仍要逐项验证 |

**关键判断：三个层次的"兼容"是独立的。** 引脚兼容不代表寄存器兼容，寄存器兼容不代表外设行为一致。**引脚兼容最容易验证（看一眼封装就够），外设行为一致最难验证（要靠实际跑通所有用到的功能）。**

### 迁移的真实成本在哪里

"换一颗国产芯片"这句话听起来很轻，实际做起来的工作量常常被低估。**真正花时间的不是改代码，而是验证那些"看起来一样但实际不一样"的地方：**

- **时钟树差异**：PLL 的倍频范围、分频系数、切换时序可能不同，导致实际主频和预期不符
- **外设行为细节**：同一个外设（比如 ADC 或定时器）在触发方式、标志位清除时机、中断响应顺序上可能有细微差异
- **Flash 特性**：等待周期设置、扇区大小、擦写寿命、读写速度都可能不一样，**Bootloader 的分区方案要重新核对**（见 [3.7 Bootloader 与 OTA 升级](../03-嵌入式软件工程/07-Bootloader与OTA升级.md)）
- **Boot ROM 与启动方式**：ISP 的入口和上位机工具不同，产线的烧录流程要跟着改
- **勘误手册（Errata）**：这是最容易被忽略的一项。**每一颗 MCU 都有自己的勘误手册**，里面写着"这个外设在某个条件下有已知问题、变通办法是什么"。换芯片意味着要把新芯片的勘误手册完整读一遍——**不读勘误就上线，是量产事故的常见来源**
- **工具链与调试器**：烧录器、调试固件、IDE 支持是否到位
- **长期供货承诺**：这一颗料三年后还在不在？做产品必须问这个问题

**所以国产替代的验收标准应该是：在真实产品上把用到的每一个外设、每一种工况都跑过一遍**，而不是"编译通过、Demo 能跑"。

### 什么时候该用、什么时候别用

**适合考虑国产 MCU 的情况**：成本敏感的量产产品、有国产化要求的行业客户、需要第二供应源做备份、中低端通用场景。

**要格外谨慎的情况**：需要车规或功能安全认证的场合（要确认型号是否有对应等级和认证文件）、对某一个外设的性能指标卡得极死的场合、团队没有余力做完整验证的场合、交期和长期供货无法确认的场合。

国产替代的详细评估方法（供货周期、停产风险、寿命、认证）见 [10.6 打样量产与国产替代](../10-硬件电路与PCB/06-打样量产与国产替代.md)，选型决策的完整流程见 [12.1 需求分析与方案选型](../12-工程素养与交付/01-需求分析与方案选型.md)。

**面试提醒**：国产 MCU 替代是这两年嵌入式面试里出现频率明显上升的话题。面试官想听的不是"我知道 GD32 能替代 STM32"，而是 **"我知道替换的时候要验证哪些东西、风险在哪里"**。能说出勘误手册、Flash 分区、外设行为差异这几条，说明你真的做过这件事。

## 怎么选你的第一块板

面对一堆平台，初学者最常犯的错误是"先买最便宜/最热门的，学了再说"。更合理的方式是按这五个问题过一遍：

| 问题 | 它决定了什么 |
|---|---|
| **你要做什么方向？** | 物联网 → ESP32；电机控制 → 带高级定时器和运放的 MCU；通用入门 → STM32 |
| **有多少资料能搜到？** | 对初学者，这一项比芯片参数更重要。资料少的平台，卡住时无人可问 |
| **外设够不够用？** | 先列出项目需要的外设（几路 PWM、几路 ADC、要不要 CAN、要不要 USB），再去对数据手册 |
| **封装能不能手工焊？** | 手工打样阶段优先选 LQFP 这类引脚外露的封装，BGA 和 QFN 需要回流焊 |
| **供货和价格能不能接受？** | 学生阶段影响小，做产品或做毕设要交付时要认真看（见 [10.6 打样量产与国产替代](../10-硬件电路与PCB/06-打样量产与国产替代.md)） |

**一个降低风险的做法：第一块板选生态最好的那一块，不要选最便宜或最新的那一块。** 入门阶段的成本大头是你的时间，不是板子的钱。

## 学习建议

1. **先选一块板，把它用透，再想第二块。** 平台上手的速度取决于底层思路的相通程度，而思路是相通的——GPIO、定时器、中断、DMA 这套模型在所有单片机上都是一回事。**学好一块，换平台就是查手册的事。**
2. **从 HAL + CubeMX 入手，遇到标准库的例程就翻译过来。** 网上大量老教程、老例程（包括江协那套）还是标准库写的，你不需要为此改学标准库——把里面的寄存器操作读懂，用 HAL 的对应接口重写一遍。这样既练了"对着手册找接口"的能力，又不会被那套已经停更的 API 绑住。
3. **不要一开始就把所有外设学一遍。** 更合理的方式是先掌握最基础、最常用的几个外设：GPIO、EXTI、TIM、PWM、ADC、UART。这些内容学完之后，已经足够支撑大多数入门项目。后续用到 I2C、SPI、CAN、DMA 等外设时，再结合具体项目去学，效率会更高，理解也会更深。
4. **入门阶段优先考虑资料密度，而不是芯片参数。** 遇到问题时能搜到答案，比主频高 20MHz 重要得多。等你有能力独立读数据手册和勘误手册时，再为了成本或性能去挑战冷门平台。
5. **至少读一次完整的数据手册**。不是翻，是从头读到尾（或者至少读完外设章节）。这是从"照例程改代码"到"能独立做选型"的分界线，方法见 [12.2 数据手册阅读方法](../12-工程素养与交付/02-数据手册阅读方法.md)。
6. **了解国产 MCU，但不要为了"政治正确"而选它。** 选型的依据永远是项目需求：成本、供货、外设、认证、验证成本。**能否替代的答案不在芯片手册里，在你的验证报告里。**
7. **面试价值**：选型题在大厂和方案公司面试中很常见——"如果要做一个 XXX，你会选什么芯片，为什么"。面试官想看的是**你有没有一套完整的判断维度**（外设需求、算力、封装、成本、供货、生态），而不是你能不能背出某个型号的参数。

## 小节总结

单片机平台选型是每个项目的第一个决定，也是约束最多的一个决定。**芯片选型的成本不在芯片本身，而在它带来的所有约束**——外设够不够、封装能不能焊、资料搜不搜得到、三年后还买不买得到。

主流平台上，**STM32 是大多数方向的默认起点**，因为它生态最厚、迁移成本最低；**Arduino 是原型验证的最快路径**，但体现不出底层能力，不适合作为求职项目的主力；**ESP32 是物联网方向最省事的选择**，短板在实时性和外设精度；**MSP430 是低功耗场景的专项方案**，不适合当主力学习平台。

国产 MCU 是国内嵌入式从业者绕不开的一课。**"兼容"要分三层看**：引脚兼容、寄存器兼容、库兼容，三者互相独立，而**外设行为一致是最难验证的一层**。迁移的真实成本不在改代码，而在验证那些"看起来一样但实际不一样"的地方——时钟树、外设细节、Flash 特性、Boot ROM、**勘误手册**、长期供货。**验收标准是"在真实产品上把每个外设每种工况都跑过一遍"，而不是"Demo 能跑"。**

最后一条判断：**单片机是起点，不是终点。** 只会操作外设，在就业市场上竞争力非常有限。真正决定岗位竞争力的是建立在单片机基础之上的进阶能力——电机控制、通信协议、实时操作系统、算法调优、代码架构、可靠性设计。本章后续的每一篇，都是在这个地基上往上叠的一层。
