# 7. 通信与物联网

**单片机本身只是"会干活的脑子"，是通信协议让它和传感器、执行器、上位机、云平台连成了一个系统。**

这一章的内容覆盖面很广，但学习方式有一条主线：**不要死记协议细节，而是学会"看时序图、看数据手册、看帧格式"这套通用方法**。所有协议本质上都在规定四件事：谁先说、什么时候说、怎么说、说完怎么确认。看懂这一套逻辑，面对任何新模块都能快速上手。

## 适合谁

- **物联网/通信方向**：全章必读。
- **汽车电子方向**：7.2 是关键（Modbus/CANopen/UDS），7.5 越来越重要。
- **软件方向通用**：7.1 必读——串口收发框架是所有通信的基础。
- **硬件方向**：7.1 建议读，RS-485/CAN 的物理层问题经常是硬件问题。

## 通读顺序建议

```
7.1 总线协议  ← 先学 UART，再学 I2C/SPI，然后 CAN/RS-485
      ↓
7.3 无线通信模块（如果要走 IoT）
      ↓
7.2 网络与应用层协议（MQTT 必学，Modbus 按行业选）
      ↓
7.4 云平台接入
      ↓
7.5 安全与加密  →  7.6 协议栈与中间件
```

## 一个必须提前建立的工程习惯

**尽早搭一套稳定的串口收发框架。**

具体来说：`DMA 接收 + 空闲中断 + 环形缓冲区 + 异步解析`。这套东西一旦搭起来，后面接任何模块（WiFi、蓝牙、4G、LoRa）都会轻松很多，不会再因为丢包和卡死而反复返工。

很多人学通信的方式是"每个模块写一遍自己的接收逻辑"，结果是每个项目都在踩同样的坑。**这套框架是这一章里投入产出比最高的东西。**

## 关于"学不完"的坦诚说明

通信协议覆盖面很广，**没有人能把所有协议都系统学完**——包括很多工作多年的人。实际情况是：学到哪一块内容，就针对性地去查那一块的资料。

本教程的目标不是让你背下所有协议，而是让你**掌握学习任何协议的方法**：拿到一个新模块，知道从数据手册的哪一页看起、知道该怎么用逻辑分析仪验证、知道通信失败时按什么顺序排查。
