# 9.1 Verilog 与 RTL 设计

> **前置知识**：无（会 C 语言、知道与或非和触发器的概念即可，不要求数字电路设计经验）
> **掌握标准**：能说清"描述电路"和"写程序"的区别，拿到一段 Verilog 能判断它是组合逻辑还是时序逻辑，并能按三段式写出一条状态机。
> **对应岗位**：FPGA 开发工程师 · 数字 IC 设计工程师 · 硬件工程师（数字方向）
> **练手建议**：先别急着写代码，用厂商自带的示例工程跑通"改一行逻辑 → 综合 → 实现 → 下载 → 看 LED 变化"这条完整链路，再回头看本篇。

## 你写的不是程序，是电路的连接方式

先说这一篇最重要的一句话：**软件是"一条指令接着一条指令执行"，FPGA 是"所有逻辑同时在工作"。**

写 C 的时候，你的脑子里有一条时间线：先算 A，再判断 B，然后调用 C。CPU 只有几个核，指令只能一个接一个地过。写 Verilog 的时候，这条时间线**不存在**。你写下的每一行，描述的是芯片内部某一块逻辑单元与信号之间的连接关系。综合工具读完之后，会在 FPGA 里真的搭出成百上千个并行的电路，你写的是"谁连着谁"，不是"先做谁后做谁"。

这个区别带来两个直接的后果。

第一，**FPGA 里没有"执行时间"，只有"信号传播延迟"**。你没法用"这一句大概花了多少毫秒"来估算性能。你要关心的是：从输入信号变化，到输出稳定下来，中间经过了几级逻辑门，这段时间能不能在下一个时钟沿到来之前稳定。这就是后面 9.2 要讲的时序分析。

第二，**并行是免费的，但也是有代价的**。想让两件事同时做，写软件要开两个线程、还要处理同步和加锁；写 Verilog 只要把两段逻辑并排放着，它们真的就在同时跑。代价是：你随手写下的每一个加法器、每一个乘法器，都会实打实地占用芯片资源。软件里多算一次不心疼，硬件里多算一次就是多一片电路。

所以学 FPGA 的第一个坎不是语法，是**把顺序思维换掉**。这个转变通常需要几周，而且是最难跨的一道坎。

## HDL 像 C，但语义完全不同

Verilog 的语法长得像 C：有 if、有 case、有运算符、有大括号式的分号。这是它最大的陷阱——**长得很像，所以人会自动用 C 的语义去理解它，然后全错。**

| 你以为的（C 的语义） | 实际的（Verilog 的语义） |
|---|---|
| `if` 是运行时判断一次 | `if` 是在描述一个多路选择器（MUX），电路一直在那里 |
| 变量赋值是"存进去" | 赋值是"接一根线"，写多遍等于多根线抢同一个点 |
| 循环是重复执行 N 次 | `for` 是复制 N 份电路，循环 1000 次就生成 1000 份硬件 |
| 函数调用有栈、有返回地址 | 模块例化是"把一块电路放进来并连线" |
| 执行完语句就结束 | 没有"结束"，电路上电后一直在跑 |

**"用顺序思维写 Verilog"为什么是最致命的错误**：它不会立刻报错。你写出来的东西综合工具能过、仿真甚至能过，但生成的电路和你脑子里想的是两个东西。典型症状是资源占用远超预期、时序怎么都收敛不了、仿真结果和上板现象对不上。

举个最常见的例子：你想"先算 a+b，再用结果算 (a+b)*c"，于是分两步写成两个中间变量。在 C 里这是省一次加法的优化；在 Verilog 里，你只是描述了两根不同名字的线，综合工具未必会复用那个加法器——它可能生成两个加法器，也可能生成一个，取决于优化策略，而不是取决于你写了几行。**你想控制电路，就得用电路的方式去描述，而不是用语句的顺序去暗示。**

## 组合逻辑：输出只取决于当前输入

组合逻辑是"没有记忆"的电路：输出是当前输入的直接函数，输入一变，输出立刻跟着变（经过几级门的延迟之后）。

它在 Verilog 里通常写成 `always @(*)` 加一堆 if/case，或者在 `assign` 语句里直接写表达式。判断方法很简单：**这段逻辑里有没有出现时钟沿**。没有，就是组合逻辑。

组合逻辑有两个绕不开的问题。

**竞争与冒险**：同一个信号经过不同长度的路径到达同一个门，到达时间不同，输出就可能瞬间抖出一个错误的窄脉冲。这就是毛刺。比如 `y = a & ~a`，理论上恒为 0，实际电路中 a 变化的那一瞬间，两个输入的到达时间不一致，输出可能蹦出一个短暂的高电平。

**毛刺在下游会被放大**：如果这个带毛刺的信号接到一个计数器的使能端，毛刺就变成了真实的计数；如果接到复位端，它就成了随机复位。组合逻辑本身没错，错的是**把组合逻辑的输出直接当控制信号用**。

解决方案不是"把逻辑写得更好"，而是**把输出用触发器寄存一拍**。寄存器只在时钟沿采样，采样时刻之外的一切抖动都被无视。这也是后面反复出现的一条经验：凡是要驱动控制、要送出去给别的模块用的信号，尽量都过一级寄存器。

另一个新手高频错误是**在组合逻辑里漏掉分支**。如果你写了 `if (sel) y = a;` 却没有写 else，语义上 y 保持原值是隐含的，工具会推断出一个锁存器（latch）来"记住"它。绝大多数情况下这不是你想要的，锁存器会带来难以分析的时序和额外的告警。**写组合逻辑时，保证每个分支都赋值，或者开头给所有输出一个默认值。**

## 时序逻辑：时钟为什么离不开

时序逻辑是"有记忆"的电路：输出不只看当前输入，还看之前的状态。它由时钟边沿驱动，写法是 `always @(posedge clk)`。

**为什么数字系统离不开时钟**：因为毛刺问题无法靠电路本身根治。信号在电路里传播需要时间，任何一条长路径上的输出都会抖。时钟提供了一个"大家统一停手、看一眼结果"的时刻。只要保证**所有信号的抖动都在下一个时钟沿之前停下**，系统就是稳定的。时钟把连续的、充满毛刺的现实世界，切成了离散的、干净的时刻。

这也解释了为什么 FPGA 里几乎所有设计都有一个主时钟，为什么"跨时钟域"是一个专门的、需要小心处理的课题（9.2 会讲）。

组合逻辑和时序逻辑的写法差异，落在下面这张表里：

| | 组合逻辑 | 时序逻辑 |
|---|---|---|
| 敏感列表 | `always @(*)` | `always @(posedge clk)` |
| 有没有记忆 | 无 | 有 |
| 输出是否随输入立刻变 | 是（带延迟） | 否，要等下一个时钟沿 |
| 常用赋值方式 | 阻塞赋值 `=` | 非阻塞赋值 `<=` |
| 典型错误 | 漏 else 推出锁存器、毛刺当控制信号 | 复位写错、赋值方式用错 |
| 资源占用 | LUT | LUT + 触发器 |

## 状态机：FPGA 里最常用的结构

状态机（有限状态机，FSM）是 FPGA 设计里出现频率最高的结构。串口收一个字节、SPI 发一帧、按键识别短按长按，背后都是一条状态机。**能不能熟练写出状态机，基本等于能不能干活。**

按写法分，状态机有一段式、两段式、三段式。

| 写法 | 结构 | 问题 |
|---|---|---|
| **一段式** | 状态跳转、次态计算、输出全挤在一个 always 块里 | 代码看着紧凑，实际难读难改，输出容易带组合毛刺，时序难收敛 |
| **两段式** | 一个时序块管状态寄存器，一个组合块管次态和输出 | 次态和输出都是组合逻辑，输出仍然有毛刺风险，组合逻辑块偏大 |
| **三段式** | 时序块管状态寄存器，组合块管次态计算，另一个块管输出 | 结构清晰，输出可以寄存（无毛刺），组合逻辑被拆开，时序更容易收敛 |

**推荐三段式**。理由不是"课本这么写"，而是它把三件事分开了：状态怎么变、下一个状态是什么、输出怎么给。分开之后，改输出不会影响跳转逻辑，时序分析也容易定位是哪一段太长。两段式在简单场景下够用，一段式在正式项目里基本不该出现。

初学者最容易踩的坑是**输出用组合逻辑**。状态机跳到某个状态，输出立刻跟着变，而状态本身是寄存器输出、变化时刻是干净的，两者的相位差就会产生毛刺。稳妥做法是让输出也走一级寄存器（业内叫"寄存输出"或 Moore 型输出），代价是晚一个周期，换来的是干净和可分析——这笔买卖通常划算。

另一个坑是**状态编码方式**。用二进制编码省触发器，用独热码（one-hot）多占触发器但译码逻辑简单、时序好、不容易出毛刺。FPGA 里触发器资源本来就富裕，**独热码通常是默认选择**，综合工具也能自动帮你转换。

## RTL 设计风格要点

**可综合与不可综合**。这是 FPGA 最经典的坑：仿真能过，综合报错或者上板行为完全不对。所谓"可综合"，是指这段描述能唯一地对应到一块真实电路。下面这些通常不可综合：

- `#10` 这类延时语句：仿真里让信号晚 10 个时间单位变化，硬件里没有"等一会儿"这种东西
- `initial` 块（部分工具允许用来初始化寄存器或存储器，但依赖厂商，不要依赖它做逻辑）
- `$display`、文件读写等系统任务：这些是仿真器给你的工具，不是电路
- `while(1)` 这类没有时钟边沿的死循环

判断标准很简单：**这段代码描述的东西，能不能画成一张电路图？** 画不出来，就不可综合。养成"写的时候就知道自己在画什么电路"的习惯，这个坑基本就避开了。

**阻塞赋值与非阻塞赋值**。规则只有两条，但必须记死：

- **组合逻辑（always @(*)）里用阻塞赋值 `=`**，顺序执行，像 C 一样，符合直觉
- **时序逻辑（always @(posedge clk)）里用非阻塞赋值 `<=`**，同一时刻所有赋值"同时"发生，正确模拟了触发器并行更新的行为

时序逻辑里误用阻塞赋值是最隐蔽的错误之一：**仿真可能给出正确结果，综合后的实际电路行为却不同**，或者反过来——仿真错、上板对。反正是仿真和硬件对不上，而你不知道该信哪个。所以在时序块里看到 `=`，先当成 bug 处理。

**复位策略**。同步复位指复位信号在时钟沿被采样，好处是干净、好分析，坏处是时钟必须在跑复位才有效。异步复位指复位信号立即生效、不需要时钟，好处是上电和异常时反应快，坏处是复位释放的时刻如果不与时钟同步，很容易踩中亚稳态。

工程上的通行做法是"**异步复位、同步释放**"——既保留立即复位的响应速度，又让释放边沿落在时钟沿上。但如果你现在只是在入门，**建议整个设计统一用同步复位**，简单、不易出错。真正要避免的是**混用**：一部分模块同步复位、一部分异步复位，那会在复位释放时产生各种你查不出来的怪现象。

**时钟使能 vs 分频**。新手很自然地会想：我要一个 1Hz 的闪烁，那就分出一个 1Hz 的时钟，然后 `always @(posedge clk_1hz)`。**这是个大坑。** 自己分出来的时钟不是全局时钟，走不到专用的时钟树资源上，会带来时钟偏斜、时序分析失效、跨时钟域等一系列问题，而且有些工具直接不给综合。

正确做法叫**时钟使能**：全局时钟永远是那一个 100MHz，你写一个计数器，每数到 5000 万就拉高一次 enable 信号，然后在 `always @(posedge clk)` 里面判断 `if (enable)`。时钟只有一个，所有逻辑都挂在它下面，只在被允许的周期干活。**FPGA 里几乎永远不需要自己分频当时钟用。**

## 开发流程：绝大部分时间花在仿真里

FPGA 的开发流程和软件差别很大，走的是一条固定的流水线：

设计（写 RTL）→ 功能仿真 → 综合 → 实现（布局布线）→ 时序分析 → 生成比特流 → 下载到板子验证。

| 步骤 | 做什么 | 关键点 |
|---|---|---|
| **设计** | 用 Verilog 描述电路 | 想清楚电路结构再动手，不要边写边试 |
| **功能仿真** | 给输入加激励，看输出波形对不对 | 也叫行为仿真，这一步不涉及真实延迟 |
| **综合** | 把 RTL 映射成 LUT、触发器、BRAM、DSP 等实际资源 | 报"不可综合"通常就是在这一步暴露 |
| **实现** | 布局布线，把资源放到芯片的具体位置上 | 耗时最长，大工程可以跑几十分钟到几小时 |
| **时序分析** | 检查所有路径能否满足建立/保持时间 | 能不能上板跑，取决于这一步而不是仿真 |
| **生成比特流** | 产出下载文件 | 前面都过了才有意义 |
| **板级验证** | 下载到 FPGA，用 LED、串口、逻辑分析仪观察 | 最后一步，出问题最难定位 |

**必须建立一个观念：绝大部分时间是在仿真里度过的。** 一个熟练的 FPGA 工程师，写代码和写测试激励、跑仿真、看波形的时间比例可能是三比七，甚至更悬殊。这和软件"写完跑一下看看"的习惯完全不同。

原因很实际：**上板之后看到的现象是"最终结果"，中间发生了什么你看不见。** LED 不亮，可能是约束写错了、可能是时钟没接上、可能是状态机卡住了、也可能是复位没释放。而仿真里你能看到每一根信号的每一个时刻，能直接看出是哪一拍出了问题。所以**在上板之前把功能仿真跑通，是唯一高效的做法**。跳过仿真的代价不是省时间，是把调试难度放大十倍。

另外要区分两种仿真：**功能仿真**（前仿真）只看逻辑对不对，不考虑真实延迟；**时序仿真**（后仿真）会带上布局布线后的真实延迟，能反映毛刺和时序违例，但跑得慢。入门阶段把功能仿真做扎实就够了，时序问题交给静态时序分析工具去判。

## 工具链与国产 FPGA 生态

**两大主流平台**：

- **Xilinx（现属 AMD）的 Vivado**：目前国内用得最多，教程、开源工程、社区问答的量级最大。入门建议从这里起步。
- **Intel/Altera 的 Quartus**：老牌工具，工控、通信、高校实验室里存量很大，很多学校教材还在用它。用哪家都行，关键是先把一家用熟。

**仿真器**：ModelSim（现属 Siemens EDA）在国内公司里用得最多，工程和学校都常见；Vivado 自带的仿真器（xsim）够入门用，省一次安装；Verilator 是开源方案，速度极快，适合大规模回归测试，但它不支持时序仿真，也不接受全部语法。入门阶段不必纠结，有什么用什么。

**国产厂商的现状**（说清楚：这个领域的国产替代在快速推进，但生态差距也是事实）：

| 厂商 | 代表产品 | 工具 |
|---|---|---|
| 紫光同创 | Logos/Titan 系列 | PDS |
| 安路科技 | EG4/PH1 系列 | TD |
| 高云半导体 | GW1N/GW2A 系列 | GOWIN EDA |
| 复旦微、京微齐力等 | 各自主打中低端或特种市场 | 各自工具链 |

现状判断：**芯片本身在中低端已经可用，性价比高，工具链也在快速补齐**；但 IP 库、参考设计、社区问答、教程的数量级和两大厂差距明显。信创、军工、通信设备这些方向对国产 FPGA 有明确需求，做这个方向值得关注。但**入门阶段不建议从国产工具起步**——你需要的不是"支持国产"，而是"遇到问题时能搜到答案"。

## 入门实践路径

下面这条路径是有顺序的，每一阶段练的东西都不一样，不要跳。

| 阶段 | 练什么 | 这一步真正学到的东西 |
|---|---|---|
| **点亮 LED** | 一个计数器 + 一个输出 | 打通工具链闭环：约束文件、引脚分配、综合实现下载 |
| **按键消抖** | 用计数器数稳定时间再确认 | 第一次直面毛刺和异步输入，理解"为什么要消抖而不是延时" |
| **分频与计数** | 时钟使能、多位计数器、参数化 | 时钟使能的正确用法，parameter 让模块可复用 |
| **串口收发** | 波特率计数 + 采样对齐 + 状态机 | FPGA 的"Hello World"，第一次做完整的收发协议 |
| **状态机做协议** | SPI、I2C 或自定义帧格式 | "把时序图翻译成状态机"的能力，这是核心职业技能 |
| **显示接口** | VGA/HDMI、数码管、OLED | 时序生成、坐标扫描、行场同步，做到这里简历上可以写了 |

再往后是 DDR 控制器、AXI 总线、SDRAM 这些。它们的共同特点是：**工程上主要用厂商提供的 IP，而不是自己写**。所以不用急着啃，等真正用到再学，重点是学会"怎么用 IP 和怎么和软核处理器协同"（9.3 会讲）。

## 装备建议

**开发板**：入门建议在 Xilinx（Artix-7 系列，如 Basys3 及各类国产 Artix-7 教学板）和 Altera/Intel（Cyclone IV/V 系列）之间选一个。这两家生态最全，教程、例程、社区问答的量级远超其他选择。价格量级：入门教学板大致 300 到 1500 元，便宜的 Cyclone IV 板一两百元也能买到，点灯、消抖、串口这些练习完全够用（价格随市场波动，这里只是量级参考，不是报价）。

**不要一上来买几千元的高端板**。DDR、PCIe 这些接口你现在用不上，而且工程里都是用 IP 跑通的，学不到底层东西。等你能写出串口和状态机之后，再按需要升级。

**仿真工具**：至少要有一个能独立跑的仿真环境。Vivado 自带的 xsim 可以先用起来；ModelSim 在国内公司里用得多，值得学。

**调试工具**：示波器和逻辑分析仪在验证实际信号时有用，但不是入门必需品。比它们更值得先学的是 **ILA（集成逻辑分析仪）**——它把探针直接插在 FPGA 内部，通过 JTAG 把真实波形抓到电脑上看。这是 FPGA 调试最有力的工具，比外部示波器直观得多，**务必尽早学会**。

## 这个方向适合谁

**适合**：想进 IC 设计、数字验证、通信设备、医疗影像、雷达、高端仪器这些方向的人；对"时序、并行、电路结构"比对"业务逻辑"更来劲的人；已经会 C 和单片机、想往下走一层搞清楚"硬件到底怎么跑起来"的人。

**不适合，或者说性价比不高**：只打算做应用层、完全不碰硬件的人；急着三个月内找到工作的转行者——这个方向前两个月曲线很平，第三个月突然变陡，很容易在这里放弃；以及**想"用 FPGA 替代单片机"的人**。

最后这条特别值得说。绝大多数控制类需求——读传感器、跑 PID、驱动电机、连个屏幕——用单片机做，成本低十倍、开发快十倍、招人也容易。**FPGA 的价值在并行、在高速、在确定性时序，不在"算得快"。** 如果你的方案里 FPGA 只是"性能更好的单片机"，那这个方案本身就是错的。

## 学习建议

1. **先仿真再上板，不要反过来。** 上板看到现象不对时，你无法判断问题出在哪一层；仿真里你能看到每一个时刻的每一根信号。这个习惯要在第一个工程就养成。
2. **抄时序图，不要抄代码。** 网上抄来的代码解决了别人的问题，未必解决你的。真正该抄的是数据手册里的时序图——把图翻译成状态机，是 FPGA 工程师的核心能力。
3. **先吃透单一时钟域的设计。** 一个时钟、一套复位、全部同步逻辑。跨时钟域等 9.2 学完再碰。新手在多个时钟域里蹦跶，只会得到一堆查不出的怪现象。
4. **接受"仿真对了、上板不对"是常态。** 出现了先查约束文件和引脚分配，再查复位和时钟，最后才怀疑逻辑。这个排查顺序能省你大量时间。
5. **不要一上手就学 AXI 和 DDR。** 那是给已经能写出串口和状态机的人准备的。基础不牢的时候学这些，只会得到一堆看不懂的 IP 配置界面。
6. **如果一个月后你还觉得"这不就是换了个语法的 C"，说明你没真的动手写过仿真激励。** 思维的转变不是读出来的，是在看到自己的"顺序逻辑"变成一堆并行电路时被撞出来的。

## 小节总结

**这一篇最重要的一句话，是"你写的不是程序，是电路的连接方式"。** 软件有执行时间，FPGA 只有信号传播延迟；软件的顺序是真实的，Verilog 里语句的先后只是描述习惯，不构成任何"先做后做"的保证。用 C 的语义去理解 Verilog，是初学者最致命也最常见的错误，而且它不会报错，只会让你在时序收敛上反复受挫。

**组合逻辑和时序逻辑的分界是"有没有时钟沿"。** 组合逻辑的输出随输入立刻变化，因此必然带毛刺，毛刺一旦被下游当控制信号用就会变成真实故障。时钟的作用就是提供一个"所有人停手、统一看一眼"的时刻，把连续而充满抖动的世界切成离散而干净的时刻。所以凡是驱动控制、送出去给别的模块用的信号，都尽量过一级寄存器。

**状态机是这个方向的基本功，写就写三段式。** 它不是审美问题：把"状态怎么变、下一个状态是什么、输出怎么给"分开，读起来清楚，时序上也好定位。输出尽量寄存，独热码通常是好选择，这两个默认值能帮你避开大部分新手坑。

**风格要点归结成三条铁律**：时序逻辑里用非阻塞赋值，组合逻辑里用阻塞赋值，两者不要混；整份设计只用一种复位风格；要慢速逻辑就用时钟使能，不要自己分频出时钟。再记住"可综合 = 能画成电路图"这条判断标准，仿真能过、综合不过的坑基本就绕开了。

**最后，仿真不是走过场，它是 FPGA 开发的主战场。** 上板是最后一步，不是第一步。上板看不到中间过程，仿真能看到每一个时刻的每一根信号——这就是为什么专业工程师在仿真里花掉的时间远多于写代码。至于"这个方向值不值得走"，判断标准很明确：如果看重的是一份并发、时序和硬件结构的确定性工作，它很值；如果只是想给单片机提速，那不该选它。
