# 11.3 电路与系统仿真

> **前置知识**：[10.1 电路与电子技术基础](../10-硬件电路与PCB/01-电路与电子技术基础.md) · [11.1 测量仪器](01-测量仪器.md)
> **掌握标准**：能用仿真工具验证电路和算法，并知道仿真的结论在什么情况下可信、什么情况下不可信
> **对应岗位**：硬件工程师 · 电源工程师 · 电机控制工程师 · 嵌入式软件工程师
> **练手建议**：用 LTspice 或类似工具仿真一个 RC 低通滤波器，扫一遍频响曲线，再实际搭出来用示波器测一次，对比两者的差异

仿真在嵌入式学习里是最容易被忽视、实际价值又很高的一块。很多人做项目的习惯是直接上板子、写代码、烧录、看现象，出了问题再一点点排查——这种方式当然能学到东西，但效率不高。尤其是在控制算法、电机系统、滤波器设计、运动学建模这些领域，**很多错误完全可以在"上硬件之前"就发现**，而上硬件之后发现它们的代价，可能是炸管子、烧电机、或者一整周的返工。

但仿真也是最容易被用错的一块。用对了，它能把排错范围缩小十倍；用错了，它给你一种虚假的安全感，让你信心满满地上电，然后看着冒烟。

## 仿真的价值与边界

这一节是全篇最需要读透的部分。搞错了这一节，后面所有工具都用不好。

**仿真真正的价值有两块：**

1. **省钱省时间。** 在电脑里改一个参数是几秒钟的事，在板子上改是改代码、编译、烧写、上电的一整套流程。调 PID 时，如果每改一组参数都要烧一次板，一天的迭代次数是个位数；在仿真里，你可以把它跑成几百次。
2. **能看到实际测不到的量。** 这是仿真被严重低估的优势。示波器只能测到板上引出来的电压；而仿真里你可以直接看到电感电流、MOS 管的瞬时损耗、电机内部的磁链、控制环路里每一个中间变量。**这些量在真实电路上要么测不到，要么测起来很贵。** 想清楚一个电路到底在怎么工作，仿真有时候比实测更直观。

**仿真的边界同样清楚，而且更要说透：**

- **模型不准，仿真就是错的。** 你用的是"理想电阻""理想电感"还是一个真实的器件模型，结果可能差出好几倍。器件模型本身的偏差，是仿真误差最大的来源。
- **寄生参数被系统性忽略。** PCB 走线的电感、焊盘的电容、探头的负载、电缆的分布参数——真实系统里这些东西无处不在，而默认的仿真里几乎没有。这也解释了为什么"仿真里干干净净的电源，实测纹波很大"。
- **仿真是确定性的，真实世界不是。** 器件有容差、温度会漂移、时钟有抖动、元器件批次之间有差异。仿真跑一次通过，只说明**在那一组参数下**能通过。
- **最贵的代价在这里：仿真通过不代表实物通过。** 仿真能证明"这个方向是对的、这个参数范围是合理的"，但**不能证明"这块板子一定能工作"**。把所有信心建立在仿真上的人，第一次上电就会付出代价。

所以正确的定位是：**仿真用来缩小区间和排除方向性错误，实测用来给结论盖章。** 先仿真把范围从"完全不知道"缩小到"大致在这附近"，然后上板子微调——这个组合比只用其中任何一种都高效得多。

## 电路仿真：SPICE 类工具能做什么

电路级的仿真是最基础、也最成熟的一块。工具通常是 SPICE 系（LTspice、ngspice、以及各家 EDA 软件里内置的仿真器，**具体软件仅作类型举例**），做法是把原理图画出来、指定激励、选择分析类型、看结果。常用的分析类型有四种，各自回答不同的问题：

| 分析类型 | 回答什么问题 | 典型用途 |
|---|---|---|
| **直流工作点** | 电路静态时各点的电压电流是多少 | 查分压、查偏置、查静态功耗、确认三极管/MOS 管工作在哪个区 |
| **瞬态分析** | 电压电流随时间怎么变化 | 看开关波形、看电容充放电、看上电冲击、看 PWM 输出 |
| **交流扫描** | 不同频率下的增益和相移是多少 | 扫滤波器的频响曲线、看环路增益与相位裕度、看运放的带宽 |
| **蒙特卡洛 / 容差分析** | 器件有偏差时结果会散开多少 | 判断设计的裕量够不够、评估采样精度、看滤波器截止频率的分布 |

**直流工作点应该永远是第一步。** 很多"波形不对"的问题，根因是静态工作点就错了——管子没导通、偏置电压不对、运放饱和了。先跑工作点，把这些一次性排掉，再看动态波形，效率高得多。

**交流扫描是电源和模拟电路最有用的一项。** 它能直接给出幅频和相频曲线，环路稳不稳定、相位裕度有多少、截止频率在哪，一扫就知道。这也是实测最难做的一件事——用信号发生器加示波器逐点扫频要花掉整个下午，仿真里几秒钟。

**蒙特卡洛分析是被严重低估的一项。** 它按器件的容差分布反复跑很多次，给出结果的分布范围。设计一个采样电路时，电阻用 1% 还是 5%、运放的增益误差会不会超标——这件事用仿真几秒钟能算出来，靠实测要测很多批板子。**留裕量不是靠感觉，是可以算的**，这一点在 [10.5 信号完整性与 EMC](../10-硬件电路与PCB/05-信号完整性与EMC.md) 和电源设计里都会用到。

## 仿真里该关注什么

新手跑仿真最常犯的错是"看一遍波形，觉得还行"，然后关掉——实际上什么也没验证。**仿真的输出不是波形，是结论**，所以要看的是那些能直接对应到设计指标的量：

- **关键节点的波形**：开关节点、驱动信号、输出端。看有没有异常的尖峰、振铃、死区时间内的问题。
- **电流**：电感电流、负载电流、浪涌电流。**电流往往是比电压更能说明问题的量**，很多电压异常追下去都是电流引起的。开关管开通瞬间的电流尖峰、电机启动的浪涌，都是典型例子。
- **功耗与热**：器件的瞬时损耗积分下来就是发热量。功率器件的温升算不清，是烧管子的常见原因。
- **裕量**：这是最该看却最容易被跳过的一项。计算值和限值之间差了多少？耐压 30V 的管子用在 24V 上，看起来够，但开关尖峰一叠加就没余量了。**仿真里看到"刚好够"就等于不够。**
- **敏感参数的变化趋势**：把输入电压、负载、温度往边界上推，看指标怎么变。**设计在标称点好看是及格线，在边界点还稳才算过关。**

## 建模问题：模型是从哪来的，可不可信

**"仿真准不准"这个问题，九成的答案在模型上。**

器件模型的来源大致有三类：**厂商提供的模型**（最可信，尤其是大厂给出的 SPICE 模型，通常经过实测校准）、**工具自带的通用库**（能覆盖常见器件，精度一般，适合做趋势判断）、**自己搭的等效模型**（比如用理想元件拼出一个电机的电气模型——灵活、直观，但**准确性取决于你的建模假设是否正确**）。

判断模型可不可信，问三个问题：

1. **这个模型覆盖了哪些非理想效应？** 一个理想电感和一个带直流电阻、带饱和电流、带寄生电容的电感模型，在高频和瞬态下的表现完全不同。
2. **工作点对得上吗？** 用真实器件在你实际工作条件下的参数去比对，而不是只看默认值。
3. **它是为哪种分析设计的？** 有些模型适合直流和低频，用在开关瞬态里就失真；有的模型专门为环路分析校准，用在瞬态里反而不准。

**一个实用的习惯：先用最简单的模型跑一遍，确认方向对不对；再换精确模型，看结果变了多少。** 如果结果差得离谱，说明你对该电路的理解里还有没搞清楚的地方——这个发现本身就是仿真最大的收获。

## 系统级仿真：控制算法与机械模型

系统级仿真关心的是"整个闭环的行为"，而不只是单个电路。这里最常用的一套工具是 **MATLAB 和 Simulink**：MATLAB 更偏数学计算、数据处理和结果分析，适合矩阵运算、绘图、离线验证算法；Simulink 更偏系统建模，适合搭建控制系统框图、信号流和物理模型，直观地看系统响应和模块之间的关系。简单说，**MATLAB 适合"算和看"，Simulink 适合"搭和跑"。**

### 控制算法：把 PID 的参数范围先跑出来

控制相关的很多问题都能抽象成"**被控对象 + 控制器**"的结构：电机调速、温度控制、平衡控制、位置控制、姿态控制，都是这个形状。你完全可以在 Simulink 里搭一个被控对象模型（比如一个直流电机模型），外面接上 PID、前馈、限幅、滤波、扰动等模块，观察整个闭环的响应。

这一步的价值在调参。新手调 PID 最常见的低效循环是"改一个参数、烧一次板、看结果"，一轮好几分钟，一天试不了几组。在仿真里，你可以直接看到**阶跃响应、超调量、调节时间、稳态误差**这些指标，并且能清楚地看出 P、I、D 三项各自在改变什么——**P 影响响应速度、I 消除稳态误差、D 抑制超调**。上板之前，你心里对参数的合理范围就已经有数了，需要现场做的只是微调。

如果继续深入，还会用到传递函数分析、状态空间建模这些方法，对应的工具是各种控制系统工具箱。**不一定一开始就掌握得很深，但要知道：控制问题可以先在电脑里验证，再搬到硬件上。**

### 运动学与动力学

机器人、机械臂、运动平台这类方向，仿真能把抽象的公式变成看得见的轨迹和动画：差速底盘的线速度与角速度分解、麦轮底盘的速度矩阵、机械臂的正逆解算、末端轨迹规划、关节空间与笛卡尔空间之间的转换、路径插值——这些都可以先在 MATLAB 里画出来、跑起来。

这样做的好处很直接：**公式推错了，画出来一眼就能看出不对**（轨迹跑到奇怪的位置、姿态翻转、关节角跳变），比在实物上调试快得多。等验证过运动学没问题，再上实物测动力学和实际误差。多体/机构运动学这类仿真有专门的多体仿真工具箱，用来验证机械结构的运动范围和干涉。

### 电路与电力电子系统

这一块面向电源、电机驱动和功率电子方向。在 Simulink 里配合电力电子仿真库（如 Simscape Electrical 一类），可以仿真很多典型系统：BLDC 电机驱动、PMSM 的 FOC 控制、Buck/Boost 变换器、电流采样网络、滤波网络、逆变器。

它的价值在于**在实物之前先判断"方向对不对"**：

- 做 Buck 电路时，提前观察输出纹波、占空比变化、负载变化对系统的影响。
- 做 FOC 控制时，提前看电流环、速度环、电角度估算是否合理。
- 做电流采样电路时，先验证采样电阻、运放增益、低通滤波参数是否匹配。

**这类系统的仿真尤其值钱，因为它们一旦直接上电调试，调不好时不仅费时间，还可能直接炸管子、烧器件。** 先仿真、再上板，在这里是省钱而不是省事。

### 信号处理与数据分析

实际项目会采集大量数据：IMU、编码器、电流、电压、振动信号。这些数据可以用 MATLAB 做数字滤波器设计、FFT 频谱分析、卡尔曼滤波验证、传感器标定和曲线拟合。

这里最实用的一个流程是：**把真实采集到的数据导入 MATLAB，离线把参数调好，再移植到单片机上。** 比起在板子上一边跑一边改参数，效率高得多——而且离线可以反复回放同一段数据，做真正的对比实验，这在实时系统里做不到。采数据的方法见 [11.1 测量仪器](01-测量仪器.md)，前面 [1.5 上位机与工具开发](../01-编程与软件基础/05-上位机与工具开发.md) 里讲的日志导出成 CSV，就是为了接上这一步。

## 软硬件联合仿真：了解即可

仿真不止在软件里跑。工业上还有一整套"在不同层级上验证模型、软件和硬件一致性"的做法，称为基于模型的设计（Model-Based Design，MBD），核心思路是：**先建模 → 仿真验证 → 自动生成代码 → 部署到硬件**。

它对应的几种验证方式，大致按"离硬件越来越近"排列：

| 方式 | 模型在哪跑 | 代码在哪跑 | 验证什么 |
|---|---|---|---|
| **MIL**（模型在环） | 电脑 | 无（还是模型） | 算法逻辑对不对 |
| **SIL**（软件在环） | 电脑 | 电脑（由模型生成的 C 代码） | 生成代码和模型行为是否一致 |
| **PIL**（处理器在环） | 电脑 | 真实单片机 | 代码在真实处理器上的行为、定点误差、执行时间 |
| **HIL**（硬件在环） | 电脑（实时仿真机） | 真实控制器 | 控制器接上"假"的被控对象，在极限工况下测，不用真的电机或电源 |

MBD 的完整流程还包括**自动代码生成**——把 Simulink 模型直接生成 C 代码，甚至生成面向具体嵌入式平台的工程。这在汽车电子、工业控制、航空航天行业里非常常见，优势是模型和代码的一致性高、算法迭代快、团队协作方便。

**对大多数求职者来说，这一节了解就够了，不必投入。** 这套方法需要配套的工具链、硬件和团队流程，个人学起来投入大、又没地方练。但**知道这条路线的存在很有必要**：它代表的是一种更工业化、更系统化的开发方式，面试时如果被问到"你们的算法怎么验证"，能说出 MIL/SIL/PIL/HIL 的区别，是很明显的加分项。真的往汽车电子、控制算法、工业软件方向走，再回来深入。

## 什么时候必须实测

**这是本篇最后、也是最该记住的一节。** 下面这些情况，仿真再漂亮也不能替代实测：

- **涉及安全的部分。** 过流保护、过温保护、绝缘、耐压、电池保护——这些一旦失效会伤人或者烧房。仿真可以帮你设计，**但保护动作的验证必须实测**。
- **器件的边界和极限。** 耐压、耐流、结温、安全工作区。模型的这些参数往往不全或者偏乐观，**真实器件在极限附近的失效模式，仿真基本给不出答案**。
- **EMC 与干扰。** 辐射、传导、串扰，高度依赖布局和寄生参数，是最难仿真的领域之一。这类问题几乎必然要送到有资质的实验室实测（相关内容见 [10.5 信号完整性与 EMC](../10-硬件电路与PCB/05-信号完整性与EMC.md)）。
- **真实的噪声与纹波。** 前面提到过的测量前提：**测出来的结果不能比自己测量系统的底噪更可信**。仿真里的噪声是模型给的，实测里的噪声是环境、布局、探头、地线一起贡献的。
- **和物理世界打交道的部分。** 摩擦、间隙、机械谐振、温升引起的参数漂移、电机的实际负载特性。这些东西的模型极难做准，**运动控制的最终性能几乎一定要靠实测调出来**。
- **量产一致性问题。** 仿真跑的是"一个"电路；量产要面对的是"一万个"电路。器件容差、批次差异、焊接一致性，这些只能靠产测数据说话。
- **最终验收。** 无论前面做了多少仿真，产品能不能交付，最终以实测数据和认证报告为准。

反过来也一样：**纯靠实测、不做仿真的开发方式同样是有问题的。** 尤其是控制算法和功率电路，没有仿真就等于用硬件在做实验，烧掉的器件和浪费的时间，很快会超过学仿真的成本。

**正确的姿势是让两者互相校准**：仿真给出预期和范围，实测验证偏差；偏差大的地方，回头去改模型或者找原因——**每一次"仿真和实测对不上"的地方，都是一次最深刻的学习机会。** 这比任何教程都值钱。

## 学习建议

1. **先从电路仿真起步，不要一上来就搭 Simulink 系统。** 用一个 RC 低通滤波器入门：跑直流工作点、跑瞬态、扫一次交流频响，然后实际搭出来用示波器测一次，把两条曲线放在一起看。这次对比会让你对"仿真能信到什么程度"建立真实的直觉，比任何讲解都有效。
2. **学 MATLAB 的顺序是：语法 → 数据 → Simulink。** 先掌握变量、矩阵、脚本、函数和基本绘图；再做到能把实验数据导入进来画出来、做简单分析；然后学 Simulink 的基本操作，会搭简单的传递函数模型和 PID 闭环。**最后一步才是按方向深入**——控制方向学控制系统建模，机器人方向学运动学与轨迹仿真，电机和电源方向学电力电子仿真库，信号处理方向学滤波和频谱分析。**不要在第一个月就把所有工具箱都装一遍。**
3. **永远先跑直流工作点。** 这个习惯能帮你排掉大部分低级错误。
4. **关注裕量，不要只看标称点。** 把输入、负载、温度推到边界，看指标退化了多少。仿真里"刚好够"就等于不够。
5. **记住仿真和实测的分工。** 仿真回答"方向和范围"，实测回答"行不行"。**仿真通过不代表实物通过**——这句话要刻在脑子里，因为忘记它的人，第一次上电就要付学费。
6. **不必追求工具的高大全。** 入门阶段的仿真需求，用免费的 SPICE 工具加基础的分析类型就能覆盖大半；MATLAB 那套工具链投入较大，可以等真的要做控制算法或者电机方向时再上。**先用简单工具把问题想清楚，比先用复杂工具把图画漂亮重要得多。**
7. **这一篇的权重取决于你的方向。** 控制算法、电机驱动、电源、信号处理这几个方向，仿真几乎每天都要用；而如果你走的是 [嵌入式 Linux](../08-嵌入式Linux/01-学习路线与环境.md) 或者应用层开发方向，仿真用得很少，读一遍知道它适合解决什么问题就够，不必专门投入时间。

## 小节总结

仿真在嵌入式学习里最被忽视，也最容易被误用。它的价值在于两点：**迭代几乎零成本**（改一个参数是几秒钟的事，不是烧一次板），以及**能看到实际测不到的量**（电感电流、管内损耗、环路内每一个中间变量）。这两种能力在控制算法、电机系统、滤波器设计和运动学建模上尤其值钱。

但它的边界同样清楚，而且更需要记住：**模型不准仿真就是错的，寄生参数被系统性忽略，仿真是确定性的而真实世界不是，仿真通过不代表实物通过。** 所以正确的定位只有一句话——仿真用来缩小区间和排除方向性错误，实测用来给结论盖章。任何把信心全部建立在仿真上的开发方式，都会在第一次上电时付代价。

电路仿真的四种分析各司其职：直流工作点是永远的第一步，瞬态看时间上的行为，交流扫描看频率响应和环路稳定性，蒙特卡洛看器件容差带来的分布。看结果的时候，真正该关注的是电流、功耗、和**裕量**——设计在标称点好看只是及格线，在边界点还稳才算过关。而所有这一切准不准，最终取决于模型从哪来、覆盖了哪些非理想效应。

系统级仿真解决的是"整个闭环"的问题：控制算法先在仿真里把 PID 的参数范围跑出来，运动学先在仿真里把轨迹画出来看一眼对不对，电力电子系统先仿真再上板以免炸管子，采集到的真实数据导入 MATLAB 离线调滤波器参数。再往上一层还有基于模型的设计和 MIL/SIL/PIL/HIL 这套验证体系，了解即可，不必投入。

最后必须实测的清单同样明确：安全和保护动作、器件的边界与极限、EMC、真实噪声、机械与摩擦这类物理效应、量产一致性、以及最终验收。**仿真的意义不是让人少做实验，而是让每一次实验都更值得做**——先想清楚要验证什么，再用仪器和板子去验证它，而不是上电之后看着现象猜。
