# 嵌入式学习指南

> 作者：VOW

## 前言

作者曾苦于学校没有完整的电控培训体系，直到现在校内也没有可供参考的公开学习路线。于是决定整理这份指南，供大家参考。

后来发现，被同样问题困扰的人远不止校内的同学：**转行想入行的人不知道该学什么，在校生不知道为什么学，在职的人不知道自己缺什么**。行业里技术资料很多，但缺少一份把"这个行业有哪些位置、每个位置要什么、该怎么一步步走过去"讲清楚的路线图。

于是有了现在这份重写后的版本。它不再局限于某个学校、某个战队，而是试图覆盖嵌入式行业的主要岗位和技术方向，让不同起点的人都能找到自己的入口。

本文由多人协作撰写，内容力求覆盖嵌入式核心技能，但受限于作者水平与经验，难免有疏漏与不足，欢迎批评指正。

## 这份教程的正确用法

**嵌入式不是靠"读"学会的，是靠"做"学会的。**

这份教程不是一本需要从头读到尾的教材，而是一张**可以按需查阅的地图 + 一条可以照着走的路线**。正确的使用方式是：**先动手做一个东西，卡在哪里，翻到哪一篇。**

每一篇开头都有四行信息，是你的导航仪：

> **前置知识**：读这一篇之前你最好已经会什么
> **掌握标准**：学完这一篇你应该能做什么（可自检）
> **对应岗位**：这一篇在哪些岗位用得上
> **练手建议**：把知识变成产出的一件具体的事

详细的阅读方法、各章难度、装备采购清单和常见学习误区，见 **[0.3 怎么用这份教程](docs/00-导读/03-怎么用这份教程.md)**。

## 先想清楚：要不要学嵌入式

**这一节放在路线之前，因为它比路线更重要。**

这份教程有 70 多篇、覆盖十几个方向，真正走完要按年算。方向选错的代价不是"白读几篇"，而是漫长的时间，以及一开始就买错的板子和仪器。嵌入式还有个和纯软件不一样的门槛：**它要求你动手——买板子、焊东西、量波形，很多问题不看波形根本查不出来。** 所以在翻开第 0 章之前，先花五分钟回答下面四个问题。

- **你想不想让机器按你的意思动起来？** 电机转起来、传感器读出数、屏幕亮起、小车跑起来——嵌入式让人上瘾的地方在这里。如果你更享受处理数据、做界面、跑模型、写业务逻辑，那软件方向可能更适合你，学习环境也更容易搭起来。这不是说嵌入式不用写代码，恰恰相反，它是"代码 + 物理世界"，两者缺一不可。
- **你能不能接受"问题看不见"？** 嵌入式的 bug 大多不给报错信息：程序不跑、外设不工作、偶发死机，编译器一切正常。定位它们靠的是示波器、逻辑分析仪、万用表，靠一行行读数据手册。**这意味着你有一半时间在和硬件、仪器打交道，而不是待在编辑器里。** 只想敲代码、不想碰仪器的人，在这个方向会持续地难受。
- **你愿不愿意同时学软件和一点硬件？** 这个行业最值钱的能力是**能判断问题出在软件还是硬件**。所以你得读得懂原理图、看得懂时序图、分得清"是代码写错了还是接线错了"。这不需要你会画板，但需要你愿意学一点——"硬件有专门的工程师做"在这里是不成立的（[0.3](docs/00-导读/03-怎么用这份教程.md) 的误区四讲的也是这件事）。
- **你现在有条件动手吗？** 一块几十到几百元的板子、一张能焊能测的桌子（宿舍桌也行）、每周几小时连续的动手时间。**嵌入式是靠动手学会的，只有看视频的时间，学不会。** 条件不够可以先攒条件，但别指望"先看视频，等有板子再动手"。

### 这几种情况，建议先别选这条路

- **明确只想写代码、不想碰硬件。** 那前端、后端这些方向更匹配，岗位也多得多，不必把嵌入式当退路。
- **指望三个月速成转行。** 这个方向的曲线前面很平，短期看不到成果是常态，急着要结果的人容易中途放弃。
- **被"嵌入式 = 机器人 / 自动驾驶 / 芯片"这类词吸引，但不想碰底层。** 这些行业确实大量需要嵌入式，可进去的第一步仍然是写驱动、调时序、量波形，跳不过去。
- **只是因为"听说好就业"。** 每条路都有人这么说，判断依据应该是你想做什么，而不是哪个词听起来稳。

### 还没到能决定的时候

这很正常，尤其是刚开始接触编程的阶段。这段时期有一件事**无论你最后选哪个方向都不亏**：

1. **把编程基础打牢**：C 语言的语法、指针、内存，以及基本的数据结构与算法（[第 1 章](docs/01-编程与软件基础/README.md)）。它是嵌入式的地基，也是很多方向的共同要求。
2. **同时多看几个方向**：前端、后端、算法、测试、游戏、上位机、CTF……每个方向花一两个小时看看"他们每天在做什么、招聘要求写什么"，比在心里反复纠结有效得多。
3. **别把"还没想好"当成停下来的理由，也别指望某个假期弯道超车**：每周三小时坚持半年，通常比突击一个假期学到的东西更多，也更不容易忘。

最后一条：**决定可以改。** 嵌入式内部各方向的公共基础高度共用，换方向的沉没成本比大多数行业低（依赖关系见 [0.2 三条路线与技能依赖](docs/00-导读/02-三条路线与技能依赖.md)）；就算最后不走这条路，你在这里练出的 C 语言功底、调试能力和工程习惯也不会白费。

## 使用说明

嵌入式各方向的基础层高度共用，所以你不需要现在就决定一辈子的方向。更现实的做法是：**先把公共基础打了，同时在项目里试不同的分支，方向感是做出来的，不是想出来的。**

也不必被这份文档的篇幅吓到。每个人走的路都不一样，找到适合自己的节奏，持续积累，终会有所成。
